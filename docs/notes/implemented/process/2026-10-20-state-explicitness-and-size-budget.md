# Note：状态显式来源禁令与规模预算（写代码质量统一规范）

状态：已实施

## 问题

AI 产码存在两类高频低质模式，且都无法在提交门禁被拦截：

1. **推演状态装正常。** 功能依赖的状态没有显式协议来源（事件帧、store 方法、用户输入、系统回调都不提供它），AI 靠启发式猜测、时间顺序推断、视觉行为反推"补"出一个内部状态，让行为表面正常。链路实际不存在：不可读、不可信、不可维护，且与"杜撰接口"相比更加隐蔽——它不是错代码，是"看起来对"的假功能。屎山由此养成。
2. **无关键规模失控。** AI 沿现有文件模式持续追加：一个模块目录被塞进几十个文件、既有文件长到几千行、一个函数塞多个职责与大量变量。现状相似被当作继续堆的理由，结构判断缺位。

## 涉及范围

- 代码/模块：`.agents/skills/answra-code/SKILL.md` 新增第 4 节"状态与行为的显式来源"、第 7 节"规模预算：函数、文件、目录"；自查清单由十二问扩为十四问；`AGENTS.md` 的 `answra-code` 指针行同步。
- 流程表面：不改变任何代码、命令或 CI 行为；为写代码与评审注入状态来源判定与规模约束。
- 相关 Note：[前置条件闸门](2026-10-20-precondition-gate.md)（无来源状态直接触发闸门停下）、[代码工程规范 skill](2026-10-20-code-standards-skill.md)。

## 流程变化

- 状态准入三问（必答）：被消费的状态字段必须能指出唯一 writer、显式来源（store 端口方法/worker 事件帧/用户输入/系统 API 四选一）、失效凭据（generation/session/runId）；答不出即不写。
- 禁推演状态：启发式合成、时间/顺序推断、视觉反推、"顺路解读"未定义含义均属违规；无协议来源 → 停下先立契约。事件未到的状态不出现，宁显示明确空/未知，不显示假中间态。
- 规模预算（软红线，例外须注释与 Note 留档）：函数一处职责（约一屏/40 行内，参数 <5，布尔实参 <2，禁模式分支混杂）；文件约 400 行检查多职责（算法、聚合、线投影、组合根按仓库榜例垂直切）；单目录约 12 个文件按子职责分目录。
- "别的文件也这么长/也这样堆"从规范上声明为无效论据。

## 决定

两条规则作为 `answra-code` 独立小节，并把"状态三问"与"规模预算"纳入自查十四问。规模预算数值是评审抓手不是硬工具门禁：当前 biome/typecheck/architecture:check 拦不住行数与职责混杂，数值由自查与评审执行。

## 曾考虑的替代方案

- **推演状态只靠防御性代码预算章节顺带提：** 状态来源合法性与防御代码是两件事（前者断源头，后者断下游谎报），混写会被当作风格偏好；独立成节并显式挂钩前置条件闸门。
- **规模用 hard max（函数 ≤30 行等）+ CI 工具强制：** 硬门禁误伤合理长例（契约注释、真实状态机）且需再引工具链；软红线 + 例外留档在当前阶段成本低、效果同向。工具化延后到出现逃逸模式。
- **文件大小交给 biome 行数警告：** 行数阈值无法表达"多职责"判定；且审计口径应按职责切分而非行数达标。

## 后果与防回退

- 评审时对"状态三问"逐字段点名；无来源状态与推演合成是强驳回项，不因功能可演示放行。
- 防反向回退：不得把"规模预算"误读为"必须预拆"，仍遵守"第二消费者才抽底座"（新目录克制、组合根薄）。
- 软红线长期未动→ 逃逸时升级为工具门禁（行数/复杂度度量）。
