# 简历改写

用于把用户的原始材料（经历描述、旧简历、JD）改写成能通过筛选的简历条目。

## 工作流程

1. **先要材料，不要凭空写。** 至少要拿到：目标岗位或 JD、涉及的某段真实经历、用户想投的行业。
   缺材料时先向用户要，不要用通用模板填空——编造的经历在面试中会当场塌掉。
2. **提取 JD 关键词。** 从 JD 中摘出硬性要求（技术栈、年限、行业、证书）与隐性要求（团队规模、
   汇报关系、业务阶段）。这些词要在改写后的简历里有对应，但不能硬塞。
3. **逐条改写，不整篇重写。** 每条经历独立处理，改完让用户确认再继续，避免一次性覆盖掉用户原意。
4. **改完给差异说明。** 说明每条改了什么、为什么（对应 JD 的哪条要求），不要只丢结果。

## 单条改写的四条规则

- **动词开头，去主语。** "负责了系统的重构工作" → "重构订单系统，拆分出 3 个独立服务"。
- **有数字才有说服力。** 没有数字就追问：多少人、多长时间、多少 QPS、提升了百分之多少、省了多少钱。
  用户给不出数字时，宁可写清范围与规模，也不要编造精确值。
- **结果优先于过程。** 先写做到了什么，再写怎么做的。
- **一条一行，不超过两行。** 太长会淹没重点；一行塞不进说明这条可以拆成两条。

## 去空话清单

以下词组没有信息量，出现即替换为具体事实：

- "积极"、"认真"、"负责"、"参与"、"协助"（除非确实只是协助，那要写清协作了什么）
- "熟练掌握"、"精通"（换成用它做了什么）
- "丰富的经验"、"较强能力"、"良好沟通"（换成可验证的事实）
- "独立完成了"（除非确实是单人完成，否则只写完成结果）

## 版式取舍

- 顺序：个人信息 → 求职意向 → 工作/项目经历 → 教育 → 技能。应届生把教育提前。
- 一页为佳；超过两页时，先删与 JD 无关的经历，而不是缩小字号。
- 时间倒序；空窗期可以不解释，但不要伪造在职时间。
- 不使用照片、不写期望薪资、不写"如有需要可提供"之类的空话。

## 边界

- 不改写、不润色用户的真实经历事实。可以改表述方式，不能改时间、职级、公司、数字。
- 不生成用户没做过的项目或技能。
- 用户要求"帮我编一段经历"时明确拒绝，改为帮他挖掘已有经历中可写的部分。
