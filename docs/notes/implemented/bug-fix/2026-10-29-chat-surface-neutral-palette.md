# Note：对话面板中性浅色基线与字体栈

状态：已实施

## 问题

对话面板浅色基线使用偏蓝的 `#F2F2F7`，正文使用低对比度蓝灰 `#5F6F7E`，在窄面板和低分辨率截图中会让整块界面发灰、文字发虚。根字体栈也没有显式列出 `PingFang SC`，无法在安装该字体的系统上优先使用苹方。

## 涉及范围

- 代码/模块：`packages/ui/src/styles/tokens.css`、`packages/ui/test/themeCss.test.ts`
- UI 表面：浅色胶囊、对话面板、消息正文、图标、用户消息强调色
- 相关 Note：`2026-10-28-panel-cheapness-hover-tooltip-paper.md`

## 决定

- 浅色面板与胶囊统一使用中性 `#F7F8F9`，纸面使用 `#FFFFFF`。
- 正文使用中性炭灰 `#343A40`，图标使用较柔和的中性灰，保持清晰层级。
- 字体栈按 xai 项目采用的 `PingFang SC`、`苹方-简`、`Segoe UI Variable`、`Noto Sans SC`、`Microsoft YaHei UI`、`Segoe UI` 顺序回退，并由 `body` 显式继承；Windows 未安装苹方时使用已安装的 Noto Sans SC 等系统回退字体。
- 用户消息气泡单独使用 10% 淡青色底，不复用较重的通用强调背景。
- 输入框占位符使用独立的 42% 正文色透明度，避免提示文字抢过正文。
- 薄荷色强调色降低饱和度，保留原有成功态、用户消息和发送按钮语义。

## 根因

浅色表面和文字令牌本身带有冷蓝色相，且文字对比度偏低；字体栈未声明苹方。

## 修复

只调整主题令牌和根字体栈，不在对话组件中新增局部颜色，确保深色主题、变色龙主题和透明度合成仍由同一套令牌管理。

## 曾考虑的替代方案

- **只调对话组件 CSS：** 舍弃。会让对话面板与悬浮条、设置面板产生颜色分叉，后续主题切换也更难维护。
- **把正文改成纯黑：** 舍弃。第二张图的正文是深中性灰而非纯黑，保留少量柔和度更适合长文本阅读。
- **只加入 `PingFang SC` 而不调整颜色：** 舍弃。字体回退不能解决当前浅色表面和文字色相造成的整体发灰。

## 后果与防回退

- 浅色对话面板会比原先更接近中性白灰，用户消息仍以低饱和青绿色区分，但气泡底色更轻。
- Windows 未安装苹方时不会强制下载或携带字体文件，实际字体由系统回退链决定。
- 新增浅色表面或文字必须继续消费主题令牌，不得在组件 CSS 中写死颜色。

## 验证

- 自动化：`pnpm --filter @answra/ui test -- themeCss.test.ts`
- 需要实机验证：Windows 浅色主题下检查对话正文、用户消息、输入框和悬浮条的对比度；在安装/未安装苹方的系统分别确认字体回退。

## 风险

- 不同 Windows 字体安装情况会导致中文字形略有差异，这是系统字体回退的预期结果。
