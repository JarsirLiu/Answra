# Note：环回登录结果页沿用站点设计系统

状态：已实施

## 问题

开发态登录用环回 HTTP 回调（`http://127.0.0.1:<port>/auth/callback`），桌面端直接回了一段最小 HTML：「登录完成 / 可以关闭这个标签页，回到 Answra 桌面端」。用户在验收时指出这个页面「跟网站前端完全不是一个风格，太丑」，浏览器授权是登录链路的最后一屏，不能是裸 HTML。

## 涉及范围

- 仅影响开发态环回回调的结果页（`apps/desktop/src/main/auth/loopbackCallback.ts`）。
- 打包版的 `answra://` 深链由系统处理，不经过这个页面。
- 不涉及站点侧代码：视觉令牌是照站点 `web/src/app/globals.css` 的设计系统复刻的。

## 影响表面

- 登录成功：品牌标识 + 成功图标 +「登录完成 / 已授权 Answra 桌面端，可以关闭这个标签页。账号与套餐信息会自动同步。」
- 用户点了「拒绝」：同一版式换成取消语义（「已取消授权 / 本次登录未完成…」）。
- 自动适配系统深浅色（`prefers-color-scheme` + `color-scheme`），不加载任何外部资源。

## 决定

- 在桌面端内联复刻站点令牌：暖中性底（`oklch(0.985 0.003 95)`）、Indigo 主色（`oklch(0.52 0.19 266)`）、发丝边框、柔和光晕与网格氛围层、14px 圆角、Geist → 系统字体回退栈，深浅两套色值。
- 语言按浏览器 `Accept-Language` 选择中/英文案，不依赖桌面端 locale（结果页由浏览器请求直接触发）。
- 结果页只做视觉呈现；回调有效性仍由 `AuthService.handleCallbackUrl` 判定，页面按 URL 是否带 `error=` 决定成功/取消文案。

## 曾考虑的替代方案

- **让站点托管结果页（回调后先回站点，再跳环回）**：舍弃。授权码回跳必须直达本机环回地址，多一跳会把一次性 code 暴露给页面脚本，也拉长了链路失败面。
- **引入共享设计令牌包，桌面端与站点复用同一份 CSS 变量**：舍弃（本轮）。会引出新的跨仓库依赖与构建约定，收益只是一个静态页；先用内联复刻并在此记录来源，等桌面端出现更多「站点风格」页面时再统一。
- **只做中英文双语同页展示**：舍弃。信息重复且观感差；`Accept-Language` 已能覆盖绝大多数场景。
- **保留裸 HTML，仅加深色背景**：舍弃。用户明确要求与站点同一视觉语言。

## 后果与防回退

- 站点若调整品牌色/圆角，这个内联页不会自动跟随；改动站点设计系统时需要同步检查本页，或在未来抽出共享令牌。
- 新增任何外部字体/图标请求都可能让结果页在离线时闪白，必须保持自包含（当前只有内联 SVG 与内联样式）。
- 架构守护 `forbidLocalListeners` 要求本文件保留 `LOOPBACK_HOST = "127.0.0.1"` 与 `app.isPackaged` 断言，重构时不得丢失。

## 验证

- `pnpm verify` 全绿（含架构守护对本文件的本地监听白名单断言）。
- 本地联调：无头浏览器走完「桌面端发起 → 站点登录 → 授权卡片点允许 → 环回回调」，浏览器落在环回结果页；`Accept-Language: zh` 显示中文成功页，带 `error=access_denied` 的回跳显示取消页。
- 深色/浅色分别在系统主题下目测，配色与站点一致。
