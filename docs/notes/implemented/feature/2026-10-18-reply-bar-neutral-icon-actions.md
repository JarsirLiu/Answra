# Note：回复条发送键与缩略图删除键改回中性图标语言

状态：已实施

## 问题

悬浮导航条第 2 段功能槽里的就地回复条，目前有两处品牌薄荷绿：发送条的「确认发送」和回复条的「取消/停止」用的是 `SurfaceButton` 的 `primary` 实底薄荷；缩略图右上角的删除键用的是「深色遮罩 + 纸白 ×」，而遮罩与纸面两个颜色都随主题取值（含跟随背景的变色龙主题），压在截图上会跟着背景泛绿。

同一根悬浮条上其它图标（模式功能、工作区入口）都是中性灰图标按钮，于是条内并列了两套强调语言：薄荷绿把视觉重心从「低调贴在角落」拉到操作键上，和导航条的既有方向（截图入口都刻意去掉常驻底色）相反。

## 涉及范围

- 代码/模块：`packages/ui/src/components/panels/ReplyBar.tsx`、`packages/ui/src/components/panels/ReplyBar.css`、`packages/ui/test/FloatingBarApp.test.tsx`。
- UI/进程/协议/持久化表面：悬浮条第 2 段功能槽内回复条的按钮视觉（仅 UI 表现层，不涉及 IPC、协议与持久化）。
- 相关 Note：[悬浮条截图入口常驻底色与超宽间距](../bug-fix/2026-10-17-floating-bar-screenshot-stuck-primary-tint.md)、[悬浮导航功能槽就地回复与 FeatureSlot 架构](../architecture/2026-10-18-in-place-reply-slot-and-feature-slot.md)、[悬浮表面视觉契约](../architecture/2026-10-11-floating-surface-visual-contract.md)。

## 决定

回复条内所有按钮统一为 `SurfaceButton` 默认变体那一套中性图标语言：透明底、`--icon` 图标色、hover 出 `--hover` 底色（发送/停止、继续截图、展开对话、收起）。发送/停止键不再保留方形尺寸特例（原 `.reply-send` / `.reply-stop` 强制 `width: var(--ctl-h)` 且 `padding: 0`），与旁边的相机键用同一个尺寸公式，视觉上就是同一组里的一个图标键。缩略图删除键因为压在截图上、透明底不可读，改用不透明 `--glass` 圆底盘 + `--icon` 图标色，hover 转 `--ink` 并轻微降亮度，仍然不使用品牌薄荷。

`variant="primary"`（薄荷实底）语义不变，只留给面板里的确认类主操作（设置保存、工作区选择文件）；回复条不再出现品牌色实底。

## 影响表面

- 发送条「确认发送」、回复条「取消回复并返回发送」去掉薄荷实底、对比文字与控件投影，方底外形与尺寸特例一并移除：现在与「继续截图」相机键同宽同高、同为透明底图标键，只有图标不同；可用性仍靠「无内容时 disabled」表达。
- 缩略图删除键从「深色遮罩 + 纸白 ×」变为主题色圆底盘 + 中性图标色；点按区域（18px）与「只移除该张截图」的行为不变。
- 回复条的价值表达从「一个主操作实底按钮」变为「一排等权图标键」，与导航条的模式功能按钮规格一致。

## 曾考虑的替代方案

- **保留发送键的 `primary` 实底，只改删除键：** 发送确实是回复条里唯一的确认动作，实底能提示「该按这个」；但正因为它被设计成整条最抢眼的元素，与悬浮条低调贴在桌面角落的目标冲突，且同一根条上两套强调语言并存，故一并改中性。
- **发送键保留 `--mint-wash` 淡绿底：** 参考模式功能的激活态；但激活态表达的是「当前选中」，用在一次性发送动作上语义不符，且仍是薄荷色，故不采用。
- **删除键保留遮罩只换颜色：** 透明底会在浅色截图上不可见，纯图标色在杂乱截图上可读性差；改用不透明 `--glass` 圆底盘，兼顾可读性与中性色。
- **只在变色龙主题下改色：** 默认主题仍是薄荷绿，没有解决「同一根条两套强调语言」的根因，且会造成主题间按钮语言不一致。

## 后果与防回退

- 回复条（`reply-bar`）内不允许再出现 `variant="primary"` 或组件级薄荷实底；主操作实底样式仍由 `SurfaceButton` 的 `primary` 变体独占。
- 回复条内的图标键不再各写尺寸特例：一律用 `SurfaceButton` 默认规格，需要不同尺寸时先问「它是否还是同一组里的图标键」。
- 压在图片上的图标按钮必须自带不透明底盘（`--glass` 一类），不要用 `--scrim` 遮罩 + 纸白图标：遮罩与纸面都随主题取值，观感不可控。
- 新增回复条按钮沿用默认变体；确需强调时先确认它是否真属于「面板里的确认类操作」。

## 验证

- `pnpm verify` 通过（biome、notes:check、typecheck、agent 13、ui 232、desktop 219、架构守护）。
