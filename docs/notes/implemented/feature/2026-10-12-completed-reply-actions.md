# Note：在完成回复下显示消息操作

状态：已实施

## 问题

对话面板在模型完成后只显示回复正文，用户没有方便的复制、评价等消息级操作入口。用户提供了 AICSS `MessageActions` 组件实现，要求在回复结束后将其放到回复下方。

## 涉及范围

- 代码/模块：`packages/ui/src/components/panels/ReplyConversationPopover.tsx` 及本地消息操作、图标、表情和样式模块。
- UI/进程/协议/持久化表面：完成态 assistant 消息底部的操作栏；不改变会话事件协议或服务端消息内容。
- 相关 Note：[回复条悬浮展开实时对话](./2026-10-12-reply-bar-hover-conversation.md)。

## 决定

复用用户提供的 `MessageActions` 组件及其图标、表情数据和 CSS Module，在每条 `status: complete` 的 assistant 消息正文下方渲染。操作栏复制当前 assistant 消息文本；流式中和中断消息不显示该完成态操作栏。

## 影响表面

- 完成回复下方出现复制、评价、表情、回复及更多操作入口；复制使用当前消息的实际文本。
- 运行中的回复不显示完成态操作栏，`finish` 后随 message status 更新显示。
- 操作状态仅存在于 renderer 当前组件实例中；服务端评价持久化、真实 Fork/朗读/举报工作流不在本次范围。

## 曾考虑的替代方案

- **只实现复制按钮：** 虽然更小，但不能复用用户明确提供的统一消息操作组件和视觉方案，因此采用其完整工具栏。
- **把操作条放到回复条横向 ticker：** ticker 只承载单行活动状态，操作面板会增加拥挤并在流式期间语义不明；放在纵向对话的完成回复下方。

## 后果与防回退

操作栏只挂在 `status: complete` 的 assistant 消息，避免流式过程中因 React key/布局变化让组件提前显示。复制文本必须取对应消息的最终内容，不能取 ticker 摘要。暂未提供后端评价持久化；无后端回调的回复、分叉和更多命令不应被视为已接入服务端能力。

## 验证

- UI 测试覆盖流式消息不显示操作栏、消息进入 `complete` 后显示操作栏，以及复制动作绑定最终消息文本。
- 运行 UI 测试、类型检查、Biome、`pnpm notes:check` 和 `git diff --check`。
