# Note：轮次内容过滤（附和音与无意义短轮不入对话）

状态：提案

## 问题

用户实测里，"嗯"这类附和音会作为独立消息上屏，与"你是谁 / 即将改动 / 提交改动"式碎句混在一起。已实施的 [candidate 轮次 settle 合并](../../implemented/feature/2026-10-22-candidate-turn-settle-merging.md) 做了两件事：把窗口内相邻轮次合并成一条、把 trim 后 `< MIN_CANDIDATE_TURN_CHARS = 2` 的轮次整轮丢弃。第二条能挡住单字"嗯"，但留下三个缺口：

1. **只按长度过滤，不按内容过滤。** "嗯嗯"、"呃那个"、"哦好"这类 2 字以上的附和音照样进对话；反过来"对"、"3"、"好"这类**有信息量**的单字确认会被同一条规则一起吞掉（那份 Note 已把这点记为已知取舍）。
2. **过滤发生在"段"而不是"轮"。** 同一句话被切成两段后，单独一段可能只剩"嗯"（丢掉合理），但也可能被误判（例如"我觉得行"被切后剩下"我觉得"与"行"，两段都不像纯附和音却被分别判定）。应当在**整轮**（合并后的语义单位）上判定。
3. **非语义声音靠文本层无法完全解决。** 叹气、吸气、键盘声、椅子响会被 VAD 判为语音并被转写成"嗯"或空串；这一部分只能靠"VAD 最短语音时长 + 整轮有效内容判定"两层兜底，无法靠单一阈值解决。

内容过滤与端点判定是**两件不同的事**：端点判定回答"这轮说完了吗"（时序、语音），内容过滤回答"这轮值不值得发给 AI"（语义、文本）。本 Note 只做后者。

## 涉及范围

- 代码/模块：`apps/agent/src/interview/turns/`（新增内容过滤层，与 `settler.ts` 同级）；`apps/agent/src/worker/host.ts`（提交前接入过滤）；`packages/shared` / `packages/ui`：零接口变更（除非需要展示"已过滤"提示）。
- UI/进程/协议/持久化表面：`turn-committed` 事件**保留被过滤的轮次**（可追溯、可回放），过滤只作用于"是否进入对话"这一步；会话存储结构不变；无新增协议。

## 提案

### 1. 判定对象：整轮，不是段

过滤在"整轮"上做：整轮文本 = 该轮内所有已确认文本按序拼接后去掉分隔。分轮由端点判定层（[turn 端点判定层提案](../architecture/2026-10-22-turn-endpoint-judge-layer.md)）或 settle 合并给出；本层只消费"整轮文本"与"整轮时长"。

### 2. 三级判定（全部为纯函数、可注入阈值）

| 级别 | 判据 | 动作 |
| --- | --- | --- |
| L1 纯附和音 | 整轮文本归一化后**只含**附和/寒暄词表中的词（允许重复与标点） | 丢弃整轮 |
| L2 无有效内容 | 剥离附和词与语气词后**没有剩余实词**（中文实词/数字/英文词/代码符号） | 丢弃整轮 |
| L3 有效内容过少 | 剩余实词少于 `TURN_MIN_CONTENT_TOKENS`（初值 2）或剩余字符数少于 `TURN_MIN_CONTENT_CHARS`（初值 4） | 丢弃整轮 |

- **词表**（中文口语，初始集，必须可注入、可校准）：`嗯、呃、啊、哦、唉、诶、唔、这个、那个、就是、然后、对、对的、是的、好的、好吧、可以、行、嗯嗯、哦哦、哈哈、哎`。**不放**入词表的是有信息量的短应答（"对"、"好"、"3"、"OK"作为独立答复时）——L1 只在"整轮**只有**这些词"时命中，单独的"对"因此不会被 L1 命中，而由 L2/L3 决定去留。
- **归一化**：全角转半角、去标点与空白、繁简与大小写统一（英文），避免"嗯。"与"嗯嗯！"形态不同导致漏判。
- **L2 的"实词"定义**要显式：汉字/字母/数字组成的 token，排除停用词表（的、了、吧、呢、啊 等）——停用词表与实词表都要有单测锁定。

### 3. 与既有规则的关系（避免两套互相打架）

- 现有 `MIN_CANDIDATE_TURN_CHARS = 2`（settle 层，长度阈值）**保留**，但语义改为"整轮长度下限"的一部分；本层的 L3 是"实词数量"维度，二者互补而不是重复。实施时需把 settle 的长度判定统一到整轮上，并同步改写已实施 Note。
- 现有"trim 后 <2 字整轮丢弃"的行为由本层 L1/L2/L3 **覆盖**（更精细），避免两处规则给出矛盾结论；实施时明确唯一事实来源。

### 4. 事件与可观测性

- `turn-committed` 仍逐轮发出，包含被过滤的轮次；过滤只影响是否 `appendUserMessage`。
- 过滤原因（`filler-only` / `no-content` / `too-short`）写入 telemetry 事件，便于用真实样本统计"过滤了多少、误杀多少"。
- **不允许静默丢弃**：如果一轮被过滤，UI 上应可提示"已忽略一句附和音"（可关闭）。理由：静默丢弃会让用户以为系统没听到，是这类"过滤类"功能最容易出信任事故的地方。

### 5. 失败与边界

- 词表/阈值缺失或非法 → 视为配置错误，**显式失败**（fail-closed：不过滤，全部放行并记录一次配置错误），不允许因词表为空而静默吞掉所有内容。
- 短段解码异常（sherpa 离线识别对 <0.3s 段会抛 Reshape 异常，adapter 已跳过）产生的空文本轮次按 L2 丢弃。
- 语音层非语义声音（叹气、键盘声）若被转写为"嗯"→ L1 命中；若被转写为空 → L2 命中；若被转写为无意义字串 → 需要 L2 的实词判定兜底。

### 6. 明确不做

- 不引入额外模型（语音事件分类、语义二分类）——先用规则 + 真实样本度量。
- 不做"该不该应答 AI"的语义判定（那是应答层的判断，且应折叠进既有应答调用）。
- 不改写转写文本内容（不删词、不改标点），过滤是**整轮级取舍**，不做句内编辑。

## 影响表面

- 进入对话的消息内容变化：附和音与无实词短轮不再进入会话；单字有效应答的取舍从"一律吞掉"改为"按实词与上下文判定"（比现状更保守地少丢内容）。
- `turn-committed` 事件序列不变（仍含被过滤轮次）；UI 需新增"已忽略"提示的可选展示。
- 会话存储不变（过滤发生在写入前）。
- 无新增协议、无新增依赖、无新增资源。

## 曾考虑的替代方案

- **用 LLM 判定"这轮是不是无意义"**：舍弃作为常规路径。判定要发生在提交瞬间，LLM 往返 1–2s 会把延迟加在每条消息上；且多数情况（纯"嗯"）用词表即可判定，规则覆盖不到的少数情况再走 LLM 也不迟——但那属于"该不该应答"层，不属于内容过滤。
- **提高长度阈值（把 `MIN_CANDIDATE_TURN_CHARS` 调大到 4~6）**：舍弃。长度与语义无关：它会连带吞掉"好的我来"这类有效短答，也拦不住"嗯嗯好的"这种长度够但无内容的长附和。
- **在语音层过滤（把 VAD 检出但时长极短的段直接丢弃）**：部分采纳为**既有能力**（`VAD_MIN_SPEECH_MS = 250` 已在过滤 <250ms 的短噪声），不作为本提案的替代方案；它无法区分"短促的'嗯'"与"短促的'对'"，而这正是文本层存在的理由。
- **把过滤交给端点判定模型**：舍弃。端点模型判的是"说完了吗"，输出是概率，不判内容；且它对 <1s 短段最不可靠。
- **让内容过滤直接删除事件（不留痕）**：舍弃。事件是排障与复盘的唯一证据；过滤与否应从事件与 telemetry 反推，而不是从事件消失反推。
- **什么都不做，靠端点判定层顺带解决**：舍弃。端点判定能减少碎轮，但"单独一句'嗯'"恰好是一个**完整且短**的轮次——判定层会认为它说完了，问题不会被顺带解决。

## 验收标准

- 可观察结果：单独一句"嗯"/"呃"/"哦"不进入对话；"嗯，我觉得可以"作为整轮进入对话；"对"这类单字有效应答不被 L1 命中（是否最终入对话由 L2/L3 与上下文决定，且行为可解释）；被过滤的轮次仍出现在 `turn-committed` 事件与遥测里。
- 自动化验证：词表命中/未命中矩阵（含全角标点、重复语气词、繁简/大小写、空文本）；实词判定（停用词表、纯数字、英文词、代码符号）；阈值注入与非法配置 fail-closed；过滤原因分类正确；与 settle 层的长度判定不产生矛盾结论（同一输入两处判定一致）。
- 需要的实机验证：Windows loopback + 带标注的真实中文面试样本，统计 ①非语义轮误发率（基线：用户截图中存在）②有效短应答误杀率 ③过滤原因分布 ④用户是否需要"已忽略"提示及其打扰程度。未完成不迁 `implemented/`。

## 风险

- **词表是经验活**：中文口语的附和音没有封闭集合，词表过窄会漏（"诶嘿"、"唔使"），过宽会误杀（"行"、"可以"在特定语境里是有信息的答复）。必须靠真实样本统计迭代，且词表改动要能追溯。
- **误杀有代价**：把"对"/"好"这类有信息量的短应答吞掉，会让对话上下文出现空洞。策略上宁可**多留**（进入对话）也不要**错杀**，因为对话里的多余短句代价远小于丢失语义——这是与"过滤噪声"直觉相反的取舍。
- **与端点判定层的耦合**：过滤的输入单位（整轮）由端点判定层定义；两层若各自定义"轮"，会出现口径不一致。两层必须共用同一"轮"定义（由本层消费端点判定层的产出，而不是自行按时间窗切）。
- **空文本轮次**：转写为空时既可能是"无意义声音"也可能是"转写失败"，两者不可仅凭空文本区分；失败应有独立的显式状态（`runtime-failed` 语义）而不是混进过滤。
- **可解释性要求**：过滤是"替用户做决定"，一旦误杀且无提示，用户会认为系统丢内容；因此"可提示 + 可追溯"不是可选项。

- 用户实测（2026-10-22）：截图中连续出现"你是谁 / 嗯 / 即将改动 / 提交改动"，即存在"纯附和音独立成消息"的实例；[面试实时语音人工试用闭环](../../implemented/feature/2026-10-22-live-audio-test-loop.md) 记录了用户可实际判断延迟、语义与端点的诉求。
- 现有规则与其已知取舍：settle 层 `MIN_CANDIDATE_TURN_CHARS = 2` 只挡单字，Note 已明确记录"把有意义的单字确认（如'对'）一并吞掉是已知取舍"（[candidate 轮次 settle 合并](../../implemented/feature/2026-10-22-candidate-turn-settle-merging.md)）。
- 语音层既有能力：`VAD_MIN_SPEECH_MS = 250` 已过滤 <250ms 的短噪声 blip（`apps/agent/src/interview/vad/config.ts:18`）；sherpa 离线识别对 <0.3s 超短段会抛 Reshape 异常并返回空文本，adapter 侧已跳过（[本地 Paraformer adapter](../../implemented/feature/2026-10-21-local-paraformer-adapter.md) 与 [本地内置 ASR 路线 Note](../architecture/2026-10-21-local-asr-paraformer-small.md)）。
- 参考实现（仅取事实，不作为代码来源）：natively-cluely-ai-assistant 用英文 backchannel 正则（`yeah|yes|yep|ok|right|sure|cool|mhm|uh-huh|oh|ah|hm|...`，允许 1–4 次重复）作为零成本预筛，并把"纯确认词"（`yeah/yes/no/sure/okay/ok/right/got it/of course/...`）整轮忽略；其词表为英文，中文必须自建，且其 LICENSE 为 source-available/非商业，不作为可移植实现来源。
- 提案阶段无词表实测数据、无过滤实现；本 Note 的词表与阈值均为初值，不得在实施前当作"已验证参数"引用。
