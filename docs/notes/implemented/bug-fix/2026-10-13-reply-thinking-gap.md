# Note：修正回复条思考流的空白与错误定位

状态：已实施

## 问题

截图答题的回复条展开面板在思考内容增长后，思考块会先显示少量内容，随后被内部封顶和位移逻辑截到视口之外；外层对话滚动还可能显示“定位到最新回复”，但思考状态与底部之间留下大片空白。

## 涉及范围

- 代码/模块：`packages/ui/src/components/chat/ThinkingReasoning.tsx`、`packages/ui/test/ReplyBarWindowApp.test.tsx`
- UI 表面：回复条展开对话面板的流式思考、外层滚动跟随和定位按钮。
- 相关 Note：[思考块默认折叠为单行摘要](../feature/2026-10-26-thinking-collapsed-summary.md)。

## 根因

思考组件在流式阶段复用了完成态的 180px 内部视口封顶与 `translateY` 位移，并在组件内维护第二个滚动层。外层 `MessageStream` 只能观察到被封顶后的布局，无法可靠判断最新思考内容是否仍在底部，导致内容被遮蔽或出现错误的跳转提示。

## 决定

流式思考使用自然内容高度，不创建内部滚动和位移；思考增量由外层消息流统一滚动。完成后的思考块仍可折叠。

后续由 [思考块默认折叠为单行摘要](../feature/2026-10-26-thinking-collapsed-summary.md) 调整：思考块默认折叠，展开也不再保留 180px 封顶滚动，改为自然高度并使用外层滚动。

## 修复

流式阶段关闭内部封顶、遮罩和自动位移，仅测量并使用完整内容高度；外层内容指纹继续包含思考活动文本，增长时由 `MessageStream` 负责跟随。

## 曾考虑的替代方案

- **继续保留思考块内部滚动并同步外层滚动：** 两层滚动的高度和滚动位置容易失配，无法稳定消除空白，因此舍弃。
- **仅调大 180px 封顶：** 只能延后截断，长思考仍会复现问题，不能解决滚动职责重复。

## 后果与防回退

流式思考较长时会增加对话内容高度，但窗口内容区仍由外层滚动承载；不要在思考进行中恢复内部滚动容器或 `translateY` 追尾逻辑。

## 验证

- UI 回归测试覆盖思考内容继续增长时内容可见、外层底部跟随以及手动上翻后显示定位按钮。
- 运行回复条 UI 测试、`pnpm notes:check`、类型检查和 `git diff --check`。
