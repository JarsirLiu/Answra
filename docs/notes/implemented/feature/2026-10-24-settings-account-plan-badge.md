# Note：账户页重排——身份头与档位徽章

状态：已实施

## 问题

设置面板「账户」页用纯文本行表达档位（`套餐 ｜ 免费版`），无任何视觉标识，用户要求"加主题 UI 风格的徽标表示会员"。首版交付把「已登录 + 徽章 + 退出登录」挤在同一行，用户第二版反馈「整个设置没有统一的样式设计」「字体一会大一会小、间距丑得不得了」「已登录/免费版/退出登录这些，完全不是正常人会做出来的设计」——真实诉求是：**照主流应用的个人资料页模式重排**（头像 + 身份主行 + 档位徽章、动作独立成行、字号层级收敛），而不是在旧行结构上贴徽章。同时旧标题逻辑（[账户行收紧 Note](2026-10-17-settings-account-row-compact-and-solid.md)）把 `AuthStatus.plan`（能力目录下发的档位名字符串）经 `PLAN_LABELS` 猜译成「免费档/会员」，与额度摘要 `/user/quota` 的 `plan_name` 形成两个语义来源，刷新时序不同步时可能显示两个不同档位。徽章配色方向用户明确否决了薄荷绿强调色（原话「不要薄荷绿！太丑了！正常用成熟的组件库的徽标就行」），后续又明确「不要大数字」。

## 涉及范围

- `packages/ui/src/components/controls/Badge.tsx` + `Badge.css`（新增）：中性药丸徽章基元。
- `packages/ui/src/components/panels/SettingsPanel.tsx`：账户页重排为身份头 + 额度区 + 动作行三段；删除「套餐」行、`PLAN_LABELS` 与旧的行内动作挤行布局。
- `packages/ui/src/components/panels/SettingsPanel.css`：新增 `.account-*` 身份头/动作行规则与 `.setting-quota-detail`；删除 `.setting-membership*`、`.setting-title`、`.setting-account-identity`、`.setting-row--static` 死规则。
- 契约（`channels.ts` 的 `AuthStatus`/`AuthQuotaInfo`）与 main 侧拉取链路不变；UI 行为变化已配测试。

## 决定

- **三段式账户页（主流个人资料页模式）**：
  1. **身份头**：24px 固定头像圆标（固定 `User` SVG 占位，不拼首字母，用户点名"固定 svg"）+ 身份主行（邮箱/用户名，`--font-md`、超出截断）+ 档位徽章贴邮箱右侧同行；
  2. **额度区**（有额度数据才渲染）：细分隔线之下「额度」标签一行、积分数值下一行（`--font-md`、tabular-nums，不放大数字），细分说明 10px，4px 细进度轨；
  3. **动作行**：细分隔线之下整行按钮——退出登录为警示色文字（`--danger`，hover `--danger-wash`，破坏性操作语义，iOS 设置页同款）；未登录为整行实底薄荷「登录」（主操作品牌色约束保留）。
- **档位徽章唯一来源是服务端额度摘要**：`quota.kind === "subscription"` → 实底（solid）徽章显示 `planName ?? "会员"`；`quota.kind === "default"` → 描边（outline）徽章显示 `planName ?? "免费版"`；拿不到 `quota` 就不渲染徽章，不猜档位语义。档位名有几档显示几档（免费版 + 基础/标准/专业/旗舰等），UI 不内置档位枚举。
- **徽章走成熟组件库的中性款**：药丸形（`border-radius: 999px`、18px 高、`--font-xs`、`--label-weight`），免费=透明底+`--edge-line` 描边，付费=`--field-strong` 实底，只消费灰阶令牌；薄荷绿继续只保留给主操作按钮（延续[行内主操作 Note](2026-10-17-settings-account-row-compact-and-solid.md) 的约束一）。
- **字号层级收敛为三档并全局统一**：身份主行 `--font-md`(12px)、正文标签 `--font-sm`(11px)、次要说明/徽章 `--font-xs`(10px)，额度数值不再另有字号；分组标题维持 `--font-md`。
- **删除「套餐 ｜ 档位名」静态行**：徽章文本即档位名，行重复无信息量。
- **`accountTitle` 删除**：会员档位展示整体让位给额度摘要徽章，`AuthStatus.plan` 不再进 UI 文案（能力目录的 `plan` 字段继续用于云端可用性判断，展示层不消费）。旧快照（无 `quota` 字段）显示「已登录」且无徽章，宁可少展示也不猜。
- 未登录身份头：图标占位头像 +「未登录」主行，下方整行「登录」主按钮；无解释文案（延续账户行 Note 的约束二）。

## 曾考虑的替代方案

- **状态行 + 徽章 + 退出按钮挤一行（首版实际交付）：** 用户直接否决——一行塞三种语义、比例失衡，不是正常设计；改为三段式。
- **头像拼邮箱首字母的 36px 大圆标（第二版实际交付）：** 用户反馈"头像能不能搞个固定的 svg？头像圆圈太大了"，且徽章不应独占次行；改为 24px 固定 SVG 圆标、徽章贴邮箱右侧。
- **「可用额度」标签 + 数值右对齐同行（历史形态）：** 用户点名"可用额度删了，我要的是额度！额度下面展示下有多少积分"；改为「额度」标签在上、积分数值在下的堆叠块。
- **额度数值放大做焦点（dashboard 大数字式）：** 用户明确「不要大数字」，小面板里大数字把层级搞乱，弃用。
- **徽章用薄荷绿系分五级配色（免费灰 + 四个付费档递进）：** 用户当场否决薄荷绿；且网关 `/user/quota` 不下发档位等级（`sort_order` 只在 payment 域接口有），按档位名硬编码分级语义会把 UI 绑死在某个种子数据版本上，两案同弃。
- **沿用 `AuthStatus.plan` 作徽章来源：** 能力目录与额度接口是两条链路，时序不同步会出现"标题一套档位、额度另一套"；2026-10-23 的统一额度展示 Note 已确立 `/user/quota` 是档位展示口径，徽章跟随该口径，弃用。
- **保留「套餐」行、徽章只放在额度区：** 状态行与额度区各挂一个档位表达，信息重复且面板高度紧张；档位名只在徽章出现一次，采纳现行方案。
- **退出登录用 danger 实底大按钮：** 破坏性但非常用操作，实底会把警示色块常驻在页面上；警示色文字 + hover 淡底足够表达，弃用实底。

## 影响表面

- 账户页整体重排为：身份头（头像/邮箱/徽章）→ 额度区（可用额度/细分说明/进度条）→ 动作行（退出登录或登录）。
- 「套餐」行消失；额度区文案（`N 积分`、`剩余 N 天`、细分说明、进度条）不变。
- 「设置」页常规/模型两组的行布局不变（48px 行高、细分隔线、行内小按钮），仅与账户页共用同一字号三档。
- `AuthStatus.plan` 字段仍在契约中，仅展示层不再消费。

## 后果与防回退

- 约束一：**徽章的唯一数据源是 `quota.kind` / `quota.planName`**；禁止恢复用 `AuthStatus.plan` 猜译档位文案的 `PLAN_LABELS` 式映射。
- 约束二：**徽章不引入新强调色**；变体只有 outline/solid 两档中性款，新增变体需重新过设计。
- 约束三：**账户页不做大数字/放大字号的焦点排版**；额度区固定为「额度」标签在上、积分数值在下的堆叠块，改回大字号或右对齐数值行需重新过设计。
- 约束四：**身份与动作分属两段**；不得把登录/退出按钮塞回身份头同一行。
- 约束五：**头像用固定 SVG 圆标（24px）**；不拼首字母、不再放大圆标。
- 约束六：`pnpm lint` 在 `SettingsPanel.css` 保持 0 警告（ascending specificity 规则顺序；`.account-footer .account-*` 覆盖 `.surface-control--*` 的规则已按此排序）。
