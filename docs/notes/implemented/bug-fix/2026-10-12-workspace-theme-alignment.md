# Note：工作区空状态与控件主题对齐

状态：已实施

## 问题

笔记本/资料工作区空目录状态的说明文本没有宽度和对齐约束，在较窄面板里从左侧溢出且行长过长；目录选择按钮使用蓝色硬编码，与应用薄荷绿主操作主题冲突。左侧目录树缺少嵌套层级线，创建操作使用大块文字按钮，选中态也与用户提供的编辑器文件树参考不同。工作区内部仍有历史 `--panel-*` 自定义属性和蓝色/灰色回退色，实际主题变量不匹配时会进一步造成视觉割裂。

## 涉及范围

- 代码/模块：`packages/ui/src/components/panels/workspace/WorkspacePanel.tsx`、`WorkspacePanel.css`、`DirectoryTree.css`
- UI/进程/协议/持久化表面：工作区未选择目录态、目录树操作、Markdown 编辑与预览控件
- 相关 Note：[工作区文件预览](../feature/2026-10-12-workspace-file-preview.md)、[工作区 Markdown 编辑器](../feature/2026-10-12-workspace-markdown-editor.md)

## 根因

空状态文案是未约束宽度的 flex 子项，无法在容器内可靠换行；按钮自行定义蓝色背景而非复用 UI 主操作控件。工作区 CSS 沿用不存在的 `--panel-muted`、`--panel-border`、`--panel-active`、`--panel-hover` 变量及字面量颜色，没有遵循全局设计令牌。

## 修复

空状态说明文案改为受最大宽度约束的段落并居中排版，目录按钮复用通用薄荷绿主操作控件。工作区内部边框、悬停、选中、错误和编辑状态色改为引用全局感知令牌，避免浅色/深色主题下回退到硬编码颜色。目录树改用紧凑的编辑器侧栏样式：轻量图标操作、目录展开箭头与文件图标分列、子目录显示竖向层级线，选中行采用中性浅底与细描边。

## 决定

- 文案设定面板内最大宽度、居中对齐和稳定行高，按钮复用 `surface-control surface-control--primary`。
- 创建操作保留，但使用图标按钮；嵌套目录用细竖线提示层级，目录行保留展开箭头和文件夹图标，文件图标按 Markdown、PDF、DOCX、图片和文本类型使用不同主题色。
- 选中项使用中性悬停底色和细描边，键盘焦点仍使用主题色焦点环。
- 工作区控件和预览边界统一消费 `--ink`、`--muted`、`--glass-line-soft`、`--hover`、`--mint-wash`、`--danger` 等现有令牌。
- 增加 UI 回归断言，确认空状态文案与主操作按钮采用对应语义类名。

## 影响表面

- 工作区无目录空状态、目录树操作、Markdown 编辑器与预览区域的颜色、边框和状态色。

## 曾考虑的替代方案

- **只修复文案居中：** 能解决截图中的文字溢出，但蓝色按钮与工作区内旧令牌仍然偏离主题，舍弃。
- **重做完整工作区导航与双栏布局：** 属于更大范围的产品交互变化，超出当前截图所指的空状态视觉缺陷，舍弃。
- **保留大块新建文字按钮和无层级线布局：** 会持续占用窄侧栏可见空间，且不符合参考图的编辑器树结构，舍弃。

## 验收标准

- 可观察结果：空状态文案在工作区内居中换行，选择目录按钮呈薄荷绿；目录树和编辑/预览控件使用应用主题令牌。
- 自动化验证：`packages/ui/test/workspace.test.tsx` 覆盖空状态语义类名及目录展开状态；运行 UI 测试和 `pnpm notes:check`。
- 需要的实机验证：Windows 桌面窗口中分别检查浅色与深色主题、无目录与已选目录状态。

## 后果与防回退

工作区样式以全局主题感知令牌为唯一颜色来源，空状态按钮沿用通用主操作控件。后续增加工作区状态时继续复用这些令牌，避免再引入专属硬编码主题。

## 验证

`pnpm --filter @answra/ui test -- workspace.test.tsx`、`pnpm notes:check`、`pnpm verify` 均通过。
