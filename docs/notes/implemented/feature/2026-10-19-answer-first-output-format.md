# Note：答题输出以答案开头

状态：已实施

## 问题

回复条是横向 ticker，从本轮回复文本的第一个字符开始滚动展示（见[回复条终态答案滚动与活动标签](../bug-fix/2026-10-12-reply-bar-final-answer-scroll.md)）。答题 profile 的 system prompt 只要求「单题：第一行以『答案：』开头」，多题则要求「原题号：答案」。实际使用中模型会先写题号、引子或说明，或者被判成多题后走「题号：答案」分支，导致回复条最先展示的不是答案，用户必须展开对话面板才能看到答案本身，与回复条「不打开面板就能看到答案」的设计目标冲突。

## 涉及范围

- 代码/模块：`apps/agent/src/conversation/profiles.ts`（`ANSWER_PROFILE.systemPrompt`）。
- UI/进程/协议/持久化表面：只改提示词文本；模型请求链路、chunk 投影、回复条渲染与会话仓储均不变。
- 相关 Note：[回复条展示标准消息活动](../feature/2026-10-12-reply-bar-stream-activities.md)。

## 决定

- 身份行改为「你是 Answra 答题助手。」；其余分节结构与禁止事项保持原样。
- 第二步增加总约束：答案永远在最前面，整条回复的第一个字符必须是「答案：」。
- 单题：只写一行「答案：\<答案\>」，这一行之前不得出现题号、题号提示、引子、说明文字或空行。
- 多题：保留每题一行的粒度，但行首固定「答案：」，题号移到行尾括号内，即「答案：\<答案\>（\<题号\>）」（如「答案：B（第12题）」）。题号仍优先用试卷上印的题号，不按图片顺序自行重新编号；试卷没印题号时用题干前 10 个字代替。
- 题号从行首移到括号内是本变更的核心：原来「题号：答案」的结构本身就与「答案在最前」互斥。

## 影响表面

- 回复条：流式阶段与终态重播都从文本开头开始，因此首字符即答案，无需展开对话面板。
- 对话面板：每行以「答案：」开头、题号在括号内；计算/编程题的额外关键步骤仍另起一行，位于答案行之后。
- 模型侧仍是单一 system prompt（profile 内），不新增工具调用、结构化输出或持久化字段。

## 曾考虑的替代方案

- **多题首行汇总全部答案（如「答案：12-B、13-正确」）：** 回复条能一次看全，但填空题与计算题答案可能较长且需要与题号对应，压缩成一行后既不好读也容易错位，因此仍采用每题一行。
- **只强化单题分支、多题保留「题号：答案」：** 改动最小，但多题场景（截图含多道题时很常见）答案依然不在最前，缺陷只修一半。
- **用竖线替代括号分隔题号：** 行更短，但题号与答案的从属关系变弱，且对「试卷没印题号时用题干前 10 个字」这种长标识更不清晰，因此舍弃。
- **在渲染层截取「答案：」之后的内容单独展示：** 需要在 UI 侧解析模型输出并处理未按格式输出的情况，等于用展示层兜住提示词不可靠性，复杂度明显更高，因此先在提示词层收敛。

## 后果与防回退

- 回复条首屏可见性依赖「整条回复第一个字符是『答案：』」这一提示词约束，任何后续修改答题提示词的变更都不得把答案移到题号、引子或说明之后。
- 多题行格式为「答案：\<答案\>（\<题号\>）」；不要退回「题号：答案」。
- 模型输出不受仓库约束，仍可能出现不遵守格式的情况；当前有意不为输出做渲染层纠偏，出现偏差时优先改提示词而不是加解析兜底。
- 该提示词没有自动化回归：答案格式是模型行为，无法在仓库测试中断言。改动后必须实机跑一次截图答题（单题与多题各一次）确认首行以「答案：」开头。

## 验证

- `pnpm exec biome check` 覆盖 `apps/agent/src/conversation/profiles.ts` 通过。
- 实机验证：应用内截图答题，确认单题回复首字符为「答案：」、多题回复每行以「答案：」开头且题号在括号内，回复条无需展开对话面板即可看到答案。
- 本变更不新增自动化测试；理由见「后果与防回退」。
