# Note：对话模式与答题模式分离

状态：已实施

## 问题

原有界面把通用 AI 对话放在笔试模式中，通用对话和截图答题还共用同一会话，使多轮上下文与答题任务无法清楚区分。

## 涉及范围

- 代码/模块：`packages/ui`、`packages/shared`、`apps/agent`
- UI/进程/协议/持久化表面：模式选择、默认面板、会话 ID、模型请求上下文。
- 相关 Note：[截图答题 V1](../../implemented/feature/2026-10-11-ephemeral-exam-image-chat-v1.md)、[拒绝 Pi Runtime](../../rejected/feature/2026-10-11-screenshot-conversation-with-pi-runtime.md)。

## 决定

- “对话”位于模式列表第一位并作为默认模式；应用启动默认收起面板，仅显示悬浮导航栏，用户按需展开。
- “答题”模式保留单一截图入口；面试和会议入口保留为禁用占位。
- 通用对话使用独立会话 ID，并将该会话的历史用户/助手消息传给模型，支持多轮交流。
- 截图答题使用另一会话 ID 和答题提示词；每次答题请求只包含本轮截图和补充文字，不使用通用对话历史。
- 两类会话共享当前模型配置和 Agent runtime，按会话 ID 隔离上下文。会话采用现有内存存储，退出应用后不恢复。

## 影响表面

- 启动后默认收起，仅显示悬浮导航栏；模式菜单依次提供“对话”“答题”“面试”“会议”。
- 通用对话可以连续追问，关闭后重新打开仍保留当前运行期间的消息。
- 答题只提供截图入口；每次答题只使用本轮截图与补充文字。
- 面试与会议目前是不可点击的占位模式，不触发未实现的工作流。

## 曾考虑的替代方案

- **继续使用同一会话 ID，只切换提示词：** 舍弃，因为消息历史会跨通用交流与答题混合。
- **创建两套 Agent worker 和模型配置：** 舍弃，因为两种模式使用相同已配置模型与 API Key，按会话 ID 隔离已满足上下文边界。
- **为通用对话加入 SQLite 持久化：** 舍弃，因为需求只要求多轮对话，没有要求重启后恢复历史；继续使用现有内存会话边界。

## 后果与防回退

- 通用对话关闭面板后会保留在当前进程会话中，应用重启后丢失。
- 通用对话历史会随每轮请求一并发送；若后续需要长会话，应另行设计上下文裁剪策略。
- 答题会话不得复用通用对话 ID，也不得把通用对话历史注入答题请求。

## 验证

- UI 测试覆盖默认模式、模式顺序、模式切换、独立会话和截图入口。
- Agent 测试覆盖通用对话多轮历史和会话隔离。
- 已通过：UI 测试（38 项）、Agent runtime 测试（5 项）、UI typecheck、Agent typecheck、Biome。
- Windows 实机输入与模式切换仍需应用启动后手工确认。
