# Note：截图回复条编辑态重构为紧凑无输入条

状态：已实施

## 问题

回复条编辑态视觉破碎且挤占空间：缩略图固定 44px 且缩略条不可收缩，多张截图时溢出盖住「继续截图」按钮；「确认发送」按钮文字在窄窗口下折成两行；条体撑满固定宽度，与悬浮胶囊的设计语言脱节。

曾试验在条内加入「补充问题」textarea，两个原因必须放弃：

1. 原生 textarea 观感与自研玻璃主题不符，改造为完全贴合主题的输入控件成本高、收益低。
2. **隐身（会议隐身）模式与条内输入根本不兼容**：回复条窗口虽有内容保护（WDA Affinity），但输入法候选窗是独立系统表面，不受内容保护——打字时候选窗会被会议软件/录屏捕获，直接暴露正在输入的内容与行为。隐身模式的核心承诺是"不被捕获发现"，条内打字打破该承诺。

## 决定

- 编辑态为单行紧凑条：`缩略条（32px 圆角缩略图，可横向滚动）+ 分隔线 + 操作组（继续截图图标键 / 确认发送主键 / 收起 ×）`，条体 `width: max-content` 贴内容自适应，`max-width: 520px` 封顶。
- **回复条内不提供任何文本输入**。补充问题只能走「AI 对话」面板的输入区（该面板是普通可见表面，不存在隐身捕获矛盾）。回复条草稿（`draft`）保持为空，仅保留属性以支持发送禁用逻辑与既有 IPC 契约。
- 不引入第三方组件库：继续消费既有 `SurfaceButton` 基元与 `tokens.css` 感知令牌，条体沿用 `floating-surface` 表面类。
- 「继续截图」改为图标按钮（aria-label 保留「继续截图」，可访问名不变）；缩略图 `alt` 使用截图文件名（`att.name`），便于逐张辨认。
- 回滚试验期加入的 `DEFAULT_CAPTURE_PROMPT` 自动填草稿逻辑（`model.ts` 常量与 `useReplyWorkflow` 写入）。
- 发送键改为**方形纯图标键**（Send 图标，主色，aria-label 保留「确认发送」），删除占位文字——文字按钮是挤占空间的元凶。
- 条内间距放宽：条体 `gap: 10px`、纵向 padding `6px`，缩略条/操作组 `gap: 6px`。
- 流式态重做：左侧**整体**为匀速滚动跑马灯（删除波形动效），原发送键位置切换为「进行中」**停止键**（Square 实心图标，主色，aria-label「取消回复并返回发送」），点击取消后回退到发送态；收起 × 保留在流式态末尾。

## 影响表面

- 截图回复条编辑态：缩略图 32px、按钮图标化、条体贴内容宽度、无输入框。
- 流式态（跑马灯）行为与结构不变。
- 依赖方向、IPC 契约、窗口生命周期均不变。

## 曾考虑的替代方案

- **在条内保留自定义样式的输入框（替换原生 textarea 观感）：** 舍弃。除观感改造成本外，根本问题是隐身模式下输入法候选窗不受内容保护，打字行为会被截图/会议软件捕获；只要隐身模式存在，回复条就不能有输入面。
- **仅在非隐身时显示条内输入框，隐身时隐藏：** 舍弃。同一表面随隐身开关增减输入能力会让交互模式不可预测，也增加两套布局的维护成本；输入统一收口到「AI 对话」面板更简单。
- **引入第三方组件库（antd / MUI / Radix）重写发送条：** 舍弃。项目令牌体系有 fade 合成与「表面完全不透明」硬约束，通用组件库的主题机制无法直接对接；发送条只是单行条，引入依赖成本远大于收益（悬浮导航自研是既有决定）。
- **缩略条改为「+1」计数徽标（只显示首张 + 数量）：** 舍弃。逐张确认/移除是既有验收标准（可移除的预览），横向滚动缩略条在 520px 封顶内已足够。
- **缩略条末尾再加「+」加号瓦片作为第二截图入口：** 舍弃。与操作组里的「继续截图」按钮产生重复可访问名（测试用 `getByRole` 严格模式会冲突），语义重复。

## 后果与防回退

- 编辑态布局约束：条体 `width: max-content; max-width: 520px`，缩略条 `min-width: 0` 可收缩并横向滚动，操作组 `flex: none`。改动回复条布局时不得移除这几组防挤占约束，否则会复现「缩略图盖住按钮 / 按钮折行」。
- **防回退硬约束：回复条编辑态不得加入任何文本输入控件（input/textarea/contentEditable）。** 隐身模式下输入法候选窗不受内容保护，条内打字会被捕获暴露；需要补充文字时引导用户打开「AI 对话」面板。
- **防回退硬约束：发送/停止键保持方形纯图标键，不得回退为带文字的宽按钮。** 流式态的停止键必须可点击取消（回退到发送态），不得降级为纯状态展示。
- 组件 CSS 仍只消费感知令牌，不出现字面量颜色；不引入第三方 UI 组件库。
