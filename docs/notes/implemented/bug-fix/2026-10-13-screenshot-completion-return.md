# Note：截图答题完成后恢复发送条

状态：已实施

## 问题

截图答题收到模型终态后，回复条只清空附件和草稿，仍停留在流式回复工作流中；用户需要手动关闭，才能回到悬浮发送条。

## 涉及范围

- 代码/模块：`packages/ui/src/app/useReplyWorkflow.ts`、`packages/ui/test/FloatingBarApp.test.tsx`
- UI/进程/协议/持久化表面：截图回复条工作流完成态、主窗口悬浮条恢复和独立回复窗口状态清理。

## 根因

`performSend` 成功后只释放附件并清空草稿，没有调用已有的 `onWorkflowFinish` 收尾回调；该回调负责清空会话临时消息并结束工作流。

## 决定

成功收到终态后，先清空截图和草稿，再调用 `onWorkflowFinish`，恢复原发送条。模型失败继续保留截图和编辑态，方便重试；取消继续回到同一发送条。

## 修复

复用工作流已有结束回调，不新增第二套完成状态或窗口控制路径。补充 UI 回归测试，确认完成后截图输入和流式回复消失、悬浮发送条恢复。

## 曾考虑的替代方案

- **让回复条窗口自行判断完成并关闭：** 会让独立窗口拥有工作流生命周期，破坏主 renderer 统一持有状态的边界，因此舍弃。
- **完成后只把 phase 改为 composing：** 会保留已完成的临时会话和回复活动，不能实现发送内容清空，因此不采用。

## 后果与防回退

成功完成后的截图和当前回复只保留在完成前的临时 UI 状态中，不自动作为下一轮输入；失败和取消的行为保持可重试/可继续截图。
