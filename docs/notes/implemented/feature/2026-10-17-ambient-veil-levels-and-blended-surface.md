# Note：变色龙隐蔽强度分档与"融底"表面

状态：已实施

## 问题

变色龙（跟随背景色）开启后，悬浮条用背景主色做表面色，但前景一律按 WCAG AA 求解、描边用文字色、投影仍是写死的深色投影。结果是：**远距离和拍照时悬浮条非常显眼**——一条深色晕影加一圈矩形描边就是最容易被注意到的信号；测量悬浮条与背景的对比度又只有 4.5:1 一档，用户无法在"看得清"和"看不出来"之间选择。

用户诉求：变色时图标与文字尽量和背景融为一体，**近距离能看清内容，别人离远看不太清、拍照更难注意到**。

## 涉及范围

- 代码/模块：`packages/ui/src/model.ts`（档位常量）、`packages/ui/src/hooks/useAmbientTheme.ts`（令牌派生）、`packages/ui/src/styles/tokens.css`（投影原始参数）、`packages/ui/src/theme.ts`（偏好读写与 `useAppTheme`）、`packages/ui/src/app/useAppearanceController.ts`、`packages/ui/src/app/ImeCandidateWindowApp.tsx`、`packages/ui/src/components/panels/SettingsPanel.tsx`/`.css`、`packages/ui/src/app/FloatingBarApp.tsx`。
- 主进程：`apps/desktop/src/main/ambient.ts`（采样区域选择）、`apps/desktop/src/main/windowCaptureProtection.ts`（新增"是否已被捕获排除"查询）。
- UI/进程/协议/持久化表面：设置面板新增「隐蔽强度」分组项；新增 localStorage 键 `answra-ambient-veil`（用户本地偏好，无 IPC/协议变化）；新增两个 CSS 原始参数（`--shadow-base`、`--shadow-ctl-base`）；变色龙下 `--line-tint` 的语义由"文字色"改为"背景色"。

## 决定

**1. 视觉原理决定只有"对比度分档"这条路。** 人眼空间分辨率随距离下降，对比敏感度在高空间频率处陡降：同样 11–12px 的字，在 40cm 处约 28 弧分高、在 3m 处约 3.8 弧分（接近视力极限），低对比的字在远距离直接掉出可见阈值；相机（色度二次采样、降噪锐化、缩略图缩放）进一步把低亮度差的小字当噪声抹平。所以档位调的是**对比度目标**，字号字重保持 11–12px/400 不加粗（加字号加粗会让远看更清楚，是反向操作）。

**2. 新增「隐蔽强度」四档，默认「隐蔽」（2:1）：**

| 档位 | 文字对比度目标 | 说明 |
| --- | --- | --- |
| `blend` 贴合 | 1.4 | 几乎完全贴背景，远距离与拍照最难察觉 |
| `veiled` 隐蔽（默认） | 2.0 | 静置融入背景，一臂距离内可读 |
| `balanced` 均衡 | 3.0 | 可读性与隐蔽性折中 |
| `readable` 清晰 | 4.5 | WCAG AA 兜底，最清晰也最显眼 |

对比度求解方向按深浅方案优先，**物理上够不到目标时改用反方向**：中亮度背景（如橙色 `#e07a5f`）向亮端最多只能到约 3:1，不改方向的话 `readable` 档会静默失效、只剩一个形似 4.5:1 的名字。

**3. 表面、描边、投影全部"融底"：** 表面继续取背景原色（不透明）；描边改为背景原色（不再画矩形轮廓）；投影 alpha 提成原始参数 `--shadow-base` / `--shadow-ctl-base`，变色龙下写 `0`（深色晕影是远距离与拍照最先暴露悬浮层的信号）。强调色随档位整体更降饱和（`accentMix` 0.7→0.55），激活底 alpha 同步降档。

**4. 隐身时取"正后方"背景：** 窗口处于内容保护（隐身）状态时不进入捕获画面，裁剪图里窗口矩形内就是它正后方的真实背景，此时直接统计该矩形（`dominantColor` 新增 `inside` 模式），比"窗口外扩环形带"的近似更准；未隐身时保持原有环形带逻辑不变。

## 影响表面

- 设置面板新增一行「隐蔽强度」：四档文字分段控件（选中态用 `--mint-wash` 淡底，不引入第二个"主操作"实底按钮），变色龙关闭时禁用，`title` 给出各档位说明。
- 悬浮条/面板/菜单/候选窗的**默认观感变淡**：默认档文字对比度从 4.5:1 降到 2:1，描边不可见、投影消失。这是有意的产品取舍，不是回归。
- 候选窗（独立窗口）读同一份档位偏好，才能与主窗口在同一背景下保持同一对比度。
- 关闭变色龙或采样失败时，两个投影参数随 `FALLBACK_TOKEN_KEYS` 一并移除，默认主题的投影与描边恢复原样。
- 低于 4.5:1 不满足 WCAG 1.4.3；`readable` 档是明确的无障碍兜底，必须始终可达 4.5:1。

## 曾考虑的替代方案

- **按需显影（静止低对比、hover/focus/面板打开切清晰档）：** 人因上更强（旁观者与照片看到的是静止态），但感知令牌在 `:root` 声明、后代 `:hover` 无法重新代入 `var()`，要么再引入一个写入方、要么让组件重声明整层令牌。本轮先做静态档位，按需显影留作下一步。
- **亮度等值 / 色度编码（亮度与背景相同，只差色相饱和）：** 对拍照最有效（灰度/缩略图几乎消失），但色觉异常用户近距离也读不出。作为最激进档需要额外的色觉安全轴验证，本轮不引入。
- **继续写死 4.5:1，靠 `--fade` 整体淡化：** `--fade` 是"整层前景淡化"，会同时压掉 focus ring 与交互态，且没有任何"目标对比度"语义，无法表达"近看清晰/远看不见"。
- **让用户直接填对比度数值 / 十六进制文字色：** 暴露实现细节，且背景色会随屏幕内容变化，固定值很快失配。
- **给文字加描边、发光或半透明来"伪装"：** 相机会把高光放大成光斑，描边反而制造高空间频率边缘，远距离更容易被注意。

## 后果与防回退

- 新增 CSS 原始参数必须同时加进 `FALLBACK_TOKEN_KEYS`，否则关闭变色龙/采样失败后内联值残留，默认主题带上一份"来自背景"的投影。
- 对比度只能由 `VEIL_PROFILES` 决定；组件样式不得再出现针对变色龙的对比度特例（尤其是加回投影或文字色描边）。
- `--line-tint` 在变色龙下是**背景色**，不是文字色：任何依赖"变色龙描边=文字色"的新样式都会失效，需要轮廓时用固有色层次或最小 alpha。
- 默认档位是"隐蔽"这一产品默认值不能悄悄改回 4.5:1；改档位默认值等于改用户观感，必须同步 Note 与用例。
- 正后方采样依赖内容保护被系统可靠支持（`isWindowCaptureProtected` 同时校验平台与 `isContentProtected()` 标志）；平台忽略该标志时不会误采自己——回落到环形带。

## 验证

- `packages/ui/test/useAmbientTheme.test.tsx`：默认档在 1.6–2.6:1 区间（深/浅/饱和/中灰背景）、`readable` 档 ≥4.5:1、四档对比度单调递减、`--shadow-base`/`--shadow-ctl-base` 为 0 且 `--line-tint` 等于 `--glass-tint`。
- `packages/ui/test/theme.test.tsx`：档位默认值与非法值回落；切换档位后用上一轮背景色立即重推导（不需要新采样），并写回"投影关闭 + 描边取背景"。
- `packages/ui/test/FloatingBarApp.test.tsx`：设置面板四档禁用/可选、`aria-pressed` 选中态、点击持久化到 `answra-ambient-veil`。
- `apps/desktop/test/ambient.test.ts`：`dominantColor` 的 `inside` 模式只认窗口矩形；窗口被捕获保护时采样结果来自正后方像素（`#0000ff`）而非环形带。
- 待实机验证：Windows 下开变色龙（默认「隐蔽」）确认悬浮条静置时几乎看不出轮廓，1m 内文字可读；切 `readable` 档恢复 AA 可读性；关隐身与开隐身分别确认取色来源不同（贴深色侧栏时后者应与正后方内容同色）。
