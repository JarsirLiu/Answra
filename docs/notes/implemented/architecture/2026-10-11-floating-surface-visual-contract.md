# Note：悬浮表面视觉契约

状态：已实施

## 问题

回复条虽然在独立 `BrowserWindow` 中接收主题变量，但组件自己定义了表面、按钮、圆角和删除控件颜色，导致它与悬浮导航栏看起来像两套产品。变色龙模式可以改变变量，却不能修复组件各自选择视觉规则的问题。

## 涉及范围

- 代码/模块：`packages/ui/src/styles/shared.css`、`FloatingBar.tsx`、`ReplyBar.tsx`、`ReplyBar.css`
- 影响表面：悬浮导航栏、独立回复条、截图附件操作、发送和关闭控件
- 相关 Note：回复工作流边界、桌面窗口控制器边界

## 决定

新增一个可复用按钮组件和一个共享表面语义：

- `floating-surface`：统一表面边框、固有背景和阴影；主导航与回复条都使用它。
- `SurfaceButton`：统一悬浮控件的浏览器归零、字体、尺寸、圆角、间距、图标颜色、悬停和按下反馈；通过 `default / primary / quiet` 选择语义变体。

回复条继续保持独立窗口和独立工作流状态，但不再自行决定表面基础颜色。所有颜色继续消费 `tokens.css` 感知令牌，因此变色龙、颜色分组和透明度会同时作用于导航和回复条。

## 模块边界

- `SurfaceButton.tsx/.css` 只定义跨表面可复用的按钮契约，不持有业务状态。
- `shared.css` 只定义跨表面可复用的表面契约，不持有业务状态。
- `FloatingBar.css` 和 `ReplyBar.css` 只定义各自布局与特殊状态，不覆盖共享表面的基础颜色。
- `ReplyBar.tsx` 只选择语义类名和图标，不直接写颜色值。

## 曾考虑的替代方案

- **复制悬浮导航栏 CSS 到回复条：** 会继续产生两套颜色和尺寸来源，舍弃。
- **将回复条并回主窗口以复用 DOM：** 会破坏已验证的独立窗口捕获兼容性，舍弃。
- **只保留语义 CSS 类、不抽 React 组件：** 回复条之前已经因浏览器默认按钮样式漏出而失控，无法保证所有调用方都使用同一套归零规则，因此改为由 `SurfaceButton` 统一入口。

## 后果与防回退

- 新增悬浮导航、浮层或任务条时，优先组合 `floating-surface` 和 `SurfaceButton`；只有明确的非按钮控件才直接使用表面令牌。
- 组件 CSS 不得重新加入硬编码表面颜色、字体颜色或阴影；颜色必须来自 `tokens.css` 感知令牌。
- 回复条仍必须通过 `ReplyBarWindowApp` 接收主 renderer 的主题变量，不能自行创建另一套主题状态。

## 验证

- 自动化：UI typecheck、UI 测试、Biome 和 Note 门禁。
- 手工检查：浅色、深色、变色龙、颜色分组和透明度状态下，导航栏与回复条应保持同一表面和控件语言。
