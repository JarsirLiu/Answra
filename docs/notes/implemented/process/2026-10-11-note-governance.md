# Note：强制中文工程 Note 治理

状态：已实施

## 问题

方案文档散落在 `docs/` 根目录，提案、已实施决定和已放弃想法没有清楚区分；功能新增、删除和缺陷修复也没有强制留下来龙去脉，未来容易重复讨论或重新引入已知问题。

## 决定

所有非机械变更必须在同一提交/PR 内新增或更新 Note。功能新增、删除、重要行为变化、跨模块契约、架构、依赖、持久化、测试策略和工具流程都属于必须留痕的范围；纯格式、typo 和纯机械重命名可豁免。

## 涉及范围

- `AGENTS.md`：仓库强制规则。
- `.agents/skills/answra-change/SKILL.md`：AI 执行步骤。
- `scripts/docs/check-notes.mjs`：Note 格式、链接与变更配对门禁。
- `package.json`、`.github/workflows/ci.yml`：本地完整验证和 CI。

Note 路径固定为 `docs/notes/<状态>/<类别>/YYYY-MM-DD-主题.md`。状态为 `proposed`、`implemented`、`rejected` 或 `archived`；类别为 `feature`、`bug-fix`、`simplification`、`architecture`、`process`、`testing`。正文使用中文，稳定代码标识保留英文。

每份 Note 必须说明问题、涉及模块/文件、决定、真实备选方案及淘汰原因、后果，并提供验收/验证证据或防止重复踩坑的约束。新增、删除和重大行为变化按 feature 记录；缺陷修复必须记录根因、修复和回归保护；删除或收缩能力必须记录移除内容和重新引入条件。

提案评审前放入 `proposed/`；实施后迁入 `implemented/` 并改写为交付事实；否决后迁入 `rejected/` 并保留理由；已失去未来指导价值的已实施记录才可归档。防回归、安全边界和重要替代方案仍有价值时不得归档。

## 工作流变化

- `.agents/skills/answra-change/SKILL.md` 是 AI 助手执行 Note 流程的必读指南。
- `pnpm notes:check` 检查 Note 目录、文件名、状态、必需章节、替代方案内容、本地 Markdown 链接，以及代码/工程流程变更是否带有 Note。
- `pnpm verify` 和 CI 都运行该门禁。CI 使用目标分支比较本次变更；本地检查暂存、未暂存和未跟踪文件。
- `docs/README.md` 是唯一文档入口；`docs/notes/` 是唯一长期方案与决策存放处。`docs/` 根目录不允许新增散落的专题方案。

## 流程变化

- 任何行为、功能、架构或工程流程变更，作者先创建拟议 Note，写明问题、影响范围、备选方案、验收/风险，再实施。
- 交付时将 Note 迁到 `implemented/` 并记录真实验证；否决时迁到 `rejected/` 并保留拒绝理由。
- 缺陷 Note 记录因果证据、根因、修复和防复发测试；能力删除 Note 记录移除范围及重新引入条件。
- 纯机械变更可豁免 Note；一旦改动涉及功能行为或设计取舍，就不能以“代码改动很小”为由豁免。

## 曾考虑的替代方案

- **平铺 `specs/` 与 `decisions/`：** 弃用。它把当前行为与取舍拆成两套文档，无法保证某次功能变更的背景、被放弃方案和防回退措施一起留存。
- **所有 Note 都要求中英文双份：** 不采用。仓库协作语言为中文，双语同步增加维护成本且不增加决策证据。
- **仅凭作者自觉补文档：** 不采用。门禁会在相关代码或工程流程变化时要求 Note，并检查 Note 结构。
- **照搬其他仓库所有索引、预算和冻结哈希系统：** 当前不采用；先强制决策完整性、生命周期和变更配对，再按真实痛点增加自动化。

## 后果与防回退

- Note 是决策与经验的可追溯记录，不再另建平铺 spec；当前约束由有效 Note 中的决定和影响范围说明。
- 自动检查能发现缺 Note 和结构不完整，但不能判断一个 Note 是否覆盖了所有独立的产品取舍。作者和评审者必须按每项独立功能/决策拆分 Note，并核对代码与 Note 一致。
- 已实施 Note 只更新其事实状态，不得悄悄改写成不同决策；新决策应新建 Note 并互相链接。
- 归档只用于失去未来指导价值的已实施记录；被拒绝的决策和防回归依据继续保留。

## 验证

- `pnpm notes:check` 在迁移后通过，缺少 Note 的工程变更会使门禁失败。
- `pnpm verify` 与 CI 都执行 Note 门禁。
