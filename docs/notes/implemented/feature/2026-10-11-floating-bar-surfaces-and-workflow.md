# Note：悬浮导航、面板与任务工作流

状态：已实施

## 问题

悬浮导航、模式菜单、二级面板、通知和截图发送条有不同的开合与恢复语义；若都当作同一种面板处理，会争用位置并互相关闭或丢失工作状态。

## 决定

悬浮导航是统一入口。面板占用互斥的内容表面槽，普通菜单和提示属于浮层，截图后的发送条属于持久任务工作流并使用独立 BrowserWindow。各表面都消费根级外观状态；隐身捕获策略由 desktop 管理，不由 UI 表面开合驱动。

## 涉及范围

- `packages/ui/src/app/surfaceState.ts` 协调面板、浮层和工作流状态。
- `packages/ui/src/components/floating-bar/` 呈现导航与浮层。
- `apps/desktop/src/main/window.ts` 创建主窗口和独立回复窗口。
- `packages/shared/src/channels.ts` 与 DesktopBridge 定义回复条状态和动作契约。

## 影响表面

- 悬浮导航是功能入口。
- 面板互斥并占用内容表面槽；菜单、通知和权限提示使用浮层宿主。
- 截图回复条是持久工作流，不因点击外部关闭；结束后恢复此前面板。

## 曾考虑的替代方案

- **把模式菜单也当成二级面板：** 会占用面板槽，无法覆盖现有面板并执行“点外部关闭”的菜单语义。
- **在主窗口内显示持久发送条：** 回复条尺寸和生命周期会改变主 HWND；Windows/Electron 捕获问题验证表明独立窗口隔离该生命周期更稳定。
- **由 renderer 决定所有窗口显隐与捕获策略：** renderer 不拥有原生窗口；策略集中在 main，避免不同功能各自重复实现。

## 后果与防回退

- 新增 UI 表面必须先说明属于面板、浮层还是持久工作流，并定义关闭、恢复、焦点和捕获行为。
- 回复工作流状态仍由主 renderer 持有，回复窗口只呈现状态并回传动作；不允许窗口之间形成互相写状态的第二条路径。
- 所有窗口内容保护效果仍需在目标 Electron 和操作系统版本实测，API 状态不能替代系统捕获验证。

## 验证

- `packages/ui/test/surfaceState.test.ts` 验证面板、浮层和工作流的状态转换。
- `packages/ui/test/FloatingBarApp.test.tsx` 验证 UI 行为。
- `apps/desktop/test/window.test.ts`、`windowIpc.test.ts` 与 `windowCaptureProtection.test.ts` 验证主进程窗口契约。

## 交互结构

悬浮导航是一条紧凑的横向工具条，始终分成三个区域：第一段选择工作模式，第二段显示该模式对应的功能，第三段放跨模式通用的笔记、资料、设置等入口。导航是统一入口；表面由应用根级协调器统一编排，分为内容表面槽和浮层宿主。

```text
AppShell
├─ FloatingBar：统一导航入口
├─ Content slot：至多一个二级面板，或一个持久任务工作流
└─ Floating layer host：模式菜单、通知和权限提示，可覆盖内容表面
```

面板和浮层共享根级主题令牌，所以图标、背景、文字、交互色和透明度一致消费变色龙/系统主题与用户外观设置。隐身的 UI 光标提示由根节点状态呈现；系统捕获保护仍由桌面主进程独立管理，不能由表面开合状态驱动。

```text
┌──────────────────┬─────────────────────────────────┬────────────────────────────┐
│ 当前模式         │ 当前模式功能                    │ 工作区                     │
│ [▣ 笔试⌄]        │ [截图] [提示] [AI 对话]         │ [笔记本] [资料] [设置] [×] │
└──────────────────┴─────────────────────────────────┴────────────────────────────┘
       点击模式选择器后浮出： [笔试] [面试] [会议]
                         ↓ 内容面板（与菜单槽位独立）
```

主导航和二级面板使用一个透明、无边框、置顶的 Electron 窗口。打开面板时窗口向下增高，导航条位置保持不变。模式菜单作为绝对定位浮层绘制在面板上方；窗口尺寸仍为其命中区域预留空间，但它不占内容面板槽。默认紧凑窗口目标约为 980 x 96 px，并限制在当前显示器可用区域内。

截图发送条是独立任务工作流，使用独立的透明 `BrowserWindow` 和 HWND。主渲染器继续持有截图附件、草稿和发送阶段，通过类型化 IPC 同步状态；回复窗口只渲染工作流并回传用户操作。回复窗口单独测量尺寸、定位到选区附近并应用捕获保护，不能通过切换主导航窗口的内容或尺寸来承载发送条。隐身模式变化必须同时更新当前存在的主窗口和回复窗口。

## 第一段：工作模式

模式菜单固定包含三个选项，顺序为 `笔试`、`面试`、`会议`。悬浮条默认显示第一项 `笔试`，同一时间只能有一个当前模式。点击当前模式选择器后展开浮层菜单；点击其他区域或按 Escape 关闭它。菜单覆盖面板，不替换或关闭面板；选择模式后菜单收起，第二段功能入口立即更新。切换本身不清空当前对话草稿或笔记。

模式代表不同工作场景，不是三套互不相干的应用。对话、笔记、设置和本地资料可以共用，第二段则提供该模式最常用的快捷入口。

## 第二段：模式功能

| 模式 | 初始入口 | 行为 |
| --- | --- | --- |
| 笔试 | 截图提问 | 添加图片到对话，预览图片、填写补充问题，并一并发送。 |
| 笔试 | AI 对话 | 打开当前会话，不覆盖已输入的草稿。 |
| 面试 | AI 建议 | 即将推出（当前占位）。 |
| 面试 | AI 对话 | 打开当前会话。 |
| 会议 | 会议记录 | 打开笔记本，记录会议要点。后续由 AI 自动记录。 |
| 会议 | AI 对话 | 打开当前会话。 |

### 面试模式的后续方向（暂不实现）

面试模式的核心能力是 **AI 建议**：帮助用户实时组织回答。它需要区分两路音频输入：

- **系统声音**：面试对方（面试官）的声音，用于检测对方的问题并触发回复建议。
- **麦克风**：用户本人的声音，作为回答上下文，让 AI 建议贴合用户已说的内容。

该功能涉及音频采集、说话人区分与实时处理，当前原型不实现，仅在工具条上保留占位入口。

### 会议模式的后续方向

会议模式的核心能力是 **AI 记录**：自动记录会议要点。当前原型由用户在笔记本中手动记录要点；后续接入系统音频后由 AI 自动提炼要点。

### 截图提问流程

1. 当前模式为 `笔试` 时，用户点击 `截图提问`，导航调用主进程区域截图（框选 overlay）。成功后主导航窗口暂时隐藏，独立回复窗口出现在选区附近。截图回复条属于**持久任务工作流表面**，占用内容表面槽，不属于面板或通知；它保留截图附件和草稿，且不因点击其他区域而关闭。
2. 回复条以占位标记显示已添加截图，不在条内解码或绘制截图像素；输入框预填一道题目的分析请求，用户可以编辑或补充上下文。
3. 回复条内提供两个入口继续向预备区追加截图：**缩略条末尾的「继续截图」加号瓦片**，以及 **「继续截图」按钮**；任一入口再次唤起区域截图，多张截图并列可单独移除。
4. 点击 **「确认发送」** 后，整条进入**流式态**：左侧波形动效传达“正在说话”的活体感，AI 回复以**匀速滚动跑马灯**在这条横条上输出（时长随文本长度线性增长以保证恒定阅读节奏），**不打开、不复用对话面板**。
5. 编辑态下用户可移除任意截图或点 **「收起回复条」**（×）放弃本轮；没有文字和截图时禁用发送按钮；流式态下点 × 即结束展示。工作流开始时暂存当前面板，结束或放弃后恢复该面板；追加截图不覆盖原恢复目标。

## 第三段：工作区与应用控制

- **笔记本**：备忘录式草稿，平时记录题目要点、文件内容或面试素材；笔试、面试时悬浮在屏幕上随时查看。切换模式不清空内容。
- **参考资料**：选择本地文件并显示文件名；原型不读取或上传文件内容。
- **设置**：打开设置面板。当前说明 AI 服务尚未配置，不能将演示值显示为可用设置。
- **关闭**：退出应用。只有实现系统托盘并明确说明后，才可以将关闭行为改成隐藏到托盘。

## 面板行为

- 根级 `surfaceReducer` 是面板槽、浮层和任务工作流的生命周期协调入口。面板互斥；导航菜单不占面板槽；任务工作流临时独占内容槽并记录被替换的面板。
- 浮层由类型决定关闭策略：模式菜单点击外部或 Escape 关闭；普通通知自动消失并可手动关闭；需要用户选择的权限提示必须显式响应，不能因点击外部消失。系统权限请求由 desktop 层发起。
- 内容面板打开时导航仍然可见；面板提供明确的关闭按钮。
- 切换模式不清除会话草稿和笔记。
- 发送前可以移除截图；没有文字和截图时禁用发送按钮。
- 后续工具运行状态应呈现为紧凑、可展开的状态行（运行中、完成、失败），而不是占据主聊天区的大块原始工具调用卡片。AG-UI/CopilotKit 事件需要映射到应用自己的呈现层。

## 原型边界

当前实现模式切换、各模式快捷入口、本地笔记、仅显示文件名的资料列表、设置占位内容，以及截图附件/补充文字/发送交互。对话回复是演示内容。桌面端区域截图通过主进程完成；浏览器预览回落文件选择。当前没有后端、模型调用、音视频采集、云端订阅或系统托盘。

## 前端技术方向

- **悬浮导航栏**：应用自研组件，不依赖通用组件库；视觉风格参考 dogsc 录屏悬浮条（白色圆角卡片、淡描边、mint 强调色、悬停黑色高亮、紧凑按钮面）。
- **对话**：接入对话功能时使用 CopilotKit（`@copilotkit/react-core` + `@copilotkit/react-ui`），通过 AG-UI 协议与后端 Agent 交互；CopilotKit 只负责 Chat 与 Agent 交互，设置页、工作区导航和业务界面仍由应用自身组件承担。
- **工具运行状态**：按面板行为一节，映射为紧凑、可展开的状态行。
- **隐身与捕获保护**：隐身开关只控制主进程捕获保护及对应 UI 表现，不与面板/浮层状态耦合。Windows 窗口排除标志需要在目标系统、截图、会议共享和录屏路径上单独实测；API 调用成功不等于所有捕获工具都按预期排除窗口。

## 验收标准

- 紧凑状态下三段始终可见，第二段随当前模式变化。
- 无需先打开二级功能菜单，即可到达设置和笔记本。
- 添加截图后显示可移除的预览；补充文字与图片作为同一条消息发送。
- 演示回复明确标识为原型内容，不伪装成模型实际结果。
- 打开或切换面板不会清空草稿和笔记内容。
- 面板打开时模式菜单可覆盖显示；点击外部或 Escape 只关闭菜单。
- 截图工作流结束或放弃后恢复此前打开的面板。
- 通知、菜单和权限提示使用浮层宿主，且各自关闭策略明确。
