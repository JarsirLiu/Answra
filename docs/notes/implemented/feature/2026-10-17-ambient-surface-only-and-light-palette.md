# Note：变色龙只接管表面固有色与浅色调色板

状态：已实施

## 问题

变色龙（跟随背景色）原本把整层前景都按背景重新求解：文字、图标、描边、强调色、投影全部由背景主色派生。浅色背景上算出来的是灰阶中低对比的文字，用户反馈「你搞的字体颜色都很糊……这种糊的字，看着非常不舒服」，并指出「像是文字，我觉得得切换颜色，而不是黑色、白色这种切换清晰度」。

同时默认（非变色龙）浅色表面是 `#F7F9FB`——一个偏冷的近纸白，与系统窗口灰阶不同源，悬浮条落在系统浅色界面上时色相不统一。

## 涉及范围

- 代码/模块：`packages/ui/src/hooks/useAmbientTheme.ts`（派生逻辑）、`packages/ui/src/theme.ts`（写入优先级）、`packages/ui/src/styles/tokens.css`（浅色调色板与投影注释）。
- UI/进程/协议/持久化表面：浅色 `--ink-tint` / `--icon-tint` / `--glass-tint` / `--panel-tint` / `--paper-tint` / `--line-tint` / `--hover-tint` / `--field-tint` 的取值变化；`data-theme` 切换逻辑不变；不动 IPC 与持久化键。
- 相关 Note：[变色龙隐蔽强度与表面融底](2026-10-17-ambient-veil-levels-and-blended-surface.md)（其"前景按对比度分档"部分被本 Note 取代）、[移除隐蔽强度四档](../simplification/2026-10-17-remove-ambient-veil-levels.md)、[输入框边界与功能图标可见性](../bug-fix/2026-10-17-ambient-control-outline-and-icon-legibility.md)。

## 决定

**1. 变色龙只写三个表面键。** `deriveAmbientTokens` 只输出 `--glass-tint`（= 背景主色原色）、`--panel-tint`（同色）、`--paper-tint`（背景向调色板纸色方向偏一档：浅底压暗 10%、深底提亮 6%）。文字、图标、描边、交互态、强调色、投影一概不写，全部来自 `[data-theme]` 调色板实色。

**2. 深浅切换仍然保留。** `resolveAmbientSchemeHysteresis` 按背景亮度（±0.07 滞回带）决定 `data-theme`，所以深色桌面上自动用深色调色板的浅字、浅色桌面上用深字——这是"切换颜色"，不是"按背景调清晰度"。文字永远是调色板实色，不会掺背景。

**3. 浅色调色板改为系统灰阶：**

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `--ink-tint` | `#1D1D1F` | 正文实色近黑 |
| `--icon-tint` | `#46464A` | 图标比正文略柔，但仍是实色 |
| `--glass-tint` / `--panel-tint` | `#F2F2F7` | 胶囊与面板同一固有色 |
| `--paper-tint` | `#FBFBFD` | 面板内纸面，比面板亮一档 |
| `--line-tint` / `--edge-tint` | `#3C3C43`（14% / 8% / 控件 16% / 24%） | 与系统控件描边同源的中性灰 |

深色调色板本轮不动。强调色继续用品牌薄荷绿（本轮不引入第二套强调色）。

**4. 投影回到调色板常量。** 变色龙不再把 `--shadow-base` / `--shadow-ctl-base` 打成 0：表面固有色已经随了背景，投影再抹掉会让条与面板完全糊在一起、失去边界感。

**5. 用户选色与变色龙的关系改为"表面优先"：** 合并顺序是 `用户分组覆盖` 铺底、`变色龙表面键` 覆盖其上。变色龙不再吞掉用户选的字色/描边色，只保留对表面三个键的独占。

## 影响表面

- 所有模式下文字都是实色：不再出现灰雾字；`前景透明度`（`--fade`）是唯一的前景淡化手段。
- 悬浮条/面板的表面固有色跟随桌面背景（变色龙开启时），落在浅色界面上与系统灰阶同源。
- 深色桌面上自动切深色调色板（浅字），浅色桌面上切浅色调色板（深字）；阈值附近仍有滞回带防抖。
- 悬浮条重新带轻投影（`--shadow-bar`），与背景同色时也能看出是一层浮起的表面。
- 变色龙开启时用户在颜色分组里选的字色/描边色仍然生效（此前会被整体忽略）。

## 曾考虑的替代方案

- **保留"按背景求解文字对比度"，只是把下限抬高：** 求解出的永远是"刚好够"的中灰，浅底上就是灰雾字；用户明确不要"调清晰度"这条路。
- **把隐身做成"整层半透明 + 背景模糊"（vibrancy，参考 natively-cluely 的浮层）：** 观感更软，但要推翻「表面恒不透明、背景零参与混色」的硬约束（拖动/滚动不改变应用颜色），且模糊区域会随桌面内容变化，代价远大于本轮收益；留作独立提案。
- **彻底去掉变色龙、只用固定调色板：** 悬浮条会与桌面背景撞色（深色桌面上的浅色条、浅色桌面上的深色条都很跳），失去"贴合背景"这个已经被验证有价值的能力。
- **让用户手填背景色/文字色：** 背景随屏幕内容变化，固定值很快失配；且暴露实现细节。
- **只给表面加半透明、文字保持实色（不做深浅切换）：** 中亮度背景上文字会与表面close到读不清，必须有调色板切换兜底。

## 后果与防回退

- `deriveAmbientTokens` 的返回值只允许包含 `--glass-tint` / `--panel-tint` / `--paper-tint`；新增任何前景键都会被"文字会变糊"这条历史缺陷反噬，必须先更新本 Note。
- 文字/图标/描边/强调色/投影只能来自 `[data-theme]` 调色板或用户颜色分组，禁止在 ambient 分支里重新按背景求解。
- `--glass-base` / `--panel-base` 恒为 1 且不乘 fade：变色龙不得写表面 alpha（拖动/滚动时颜色不得抖动）。
- 合并顺序固定为"用户分组铺底 → 变色龙表面覆盖"；不得改回"变色龙开启时用户分组全部失效"。
- 浅色调色板的取值以本文表格为准；改值属用户观感变更，需要同步 Note 与用例。

## 验证

- `packages/ui/test/useAmbientTheme.test.tsx`：胶囊与面板等于背景原色；纸面与背景不同且浅底更暗/深底更亮；断言不写文字、图标、描边、交互态、强调、投影等键；不写表面 alpha。
- `packages/ui/test/theme.test.tsx`：变色龙开启时 `--glass-tint`/`--panel-tint` 取采样色且用户选的字色/描边色仍然生效；关闭后表面内联值清除；相同 hex 的重复推送不重写令牌。
- `packages/ui/test/ImeCandidateWindowApp.test.tsx`：候选窗只继承表面固有色与 `--fade`，不再写内联文字色。
- `packages/ui` 全部 206 个测试通过；`pnpm verify` 通过。
- 待实机验证：浅色桌面上条与面板为 `#F2F2F7`、正文近黑不糊；深色桌面自动切深色调色板；切换深浅时不闪烁（滞回带生效）。
