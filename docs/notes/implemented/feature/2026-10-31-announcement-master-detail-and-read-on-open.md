# Note：公告中心重构为「列表 + 详情」两级导航，已读改为打开即标记

状态：已实施

## 问题

用户在设置面板「公告」Tab 看到两个设计腐化信号（附带截图）：

1. 已读标记是一个「✓ 已读」文字按钮（`SurfaceButton` quiet 变体 + lucide Check + 中文文案），在紧凑列表里视觉重量过大，与面板既有的成熟图标控件体系（PanelShell 关闭钮、消息操作条、悬浮条图标钮）不一致。用户裁定：这类"用大号文字装状态"的设计必须重构掉，防止继续腐化桌面端设计。
2. 公告正文整段内联在列表条目里，列表没有详情页：长公告在列表里被撑爆，列表失去信息密度（标题/日期/状态）应有的导航作用。

## 涉及范围

- 代码/模块：`packages/ui/src/components/panels/AnnouncementList.tsx` + `AnnouncementList.css`（列表条目结构与交互整体重写）；`onMarkRead` bridge 契约（`markAnnouncementRead` IPC）与未读数据流不变。
- UI 行为变化：公告 Tab 从单级列表变为「列表 → 详情」两级导航；已读语义从"手动点击按钮"变为"打开详情即标记"。
- 相关 Note：[设置中枢 Tab 整合](../feature/2026-10-20-settings-hub-tabs-account-announcements.md)（公告并入设置面板 Tab、Tab 未读角标语义）、[受保护的桌面公告中心](../feature/2026-10-17-desktop-announcement-center.md)（公告数据与未读状态的唯一来源）。原 Note 中"面板内可标记已读"的交互描述由本 Note 迭代取代。
- 三方契约：无 IPC/协议/持久化变化；`desktopAnnouncements` 数组与 `readAt` 字段语义不变。

## 决定

1. **两级导航**：列表条目只承担导航（标题、日期、未读点、chevron），正文全部收进详情页；详情页带「返回公告列表」导航，正文按 `pre-wrap` 全文渲染。选中态是 `AnnouncementList` 本地 UI 状态，不进 portal/共享层。
2. **打开即已读**（用户拍板，通知中心的标准做法）：点开未读条目时自动调用 `markAnnouncementRead`；列表项的未读信号收敛为一个红点（`--danger`）+ 标题字重，未读 Tab 角标（`PanelTab.badge`）由父级状态自然更新。「✓ 已读」按钮从产品中删除。
3. **失败路径**：标记已读失败时错误提示留在详情页内（`role="alert"`），条目保持未读；返回列表重新进入同一公告即自然重试，不设专门的"重试"控件。
4. **防腐化约束**（用户明确要求）：列表内不得再内联长正文；操作控件如果要带文字标注，必须是表单主操作/次操作（如「保存」「清除」），纯状态操作（如标记已读）只允许 icon-only 控件——本交互选了更彻底的方案：无控件。

## 修复

- `AnnouncementList.tsx`：列表态渲染紧凑可点条目（原生 `button`，hover 用 `--hover`）；选中态渲染详情（返回钮 + 标题 + 日期 + 全文 + 可能的错误）。选中条目被数组移除（登出/刷新竞态）时自动退回列表。
- `AnnouncementList.css`：条目行高、未读点、详情排版全部走既有令牌（`--ink/--muted/--danger/--hover/--glass-line-soft/--font-sm/--font-xs`），不引入新颜色与新控件变体。
- `themeCss.test.ts` 的公告 CSS 令牌守卫从 `var(--danger-wash)` 更新为 `var(--danger)`（守卫意图是"状态色必须来自语义令牌"，未读标识的载体从红底徽章换成了红点）。

## 曾考虑的替代方案

- **详情页保留 icon-only 勾选按钮手动标记已读：** 首轮提案；用户在两案中拍板"打开即已读"。舍弃理由：纯状态操作既已无一等控件，手动路径只会把同一语义分裂成两条。
- **展开/收起（accordion）替代详情页：** 舍弃。长公告仍然挤压列表，且没有全文阅读的稳定版式；详情页才承载"查看完整内容"的诉求。
- **「全部标为已读」批量动作：** 舍弃。通知密度低（角标上限 9+），为它加一级操作位得不偿失；打开详情已是逐条自然清零。
- **系统通知：** 与 2026-10-17 Note 裁定冲突（公告只在应用内渲染），不再议。

## 后果与防回退

- 约束一：公告列表条目必须保持"导航版式"——不放正文；把正文塞回列表即回退腐化，评审按本 Note 阻断。
- 约束二：纯状态操作（已读、启用、订阅这类）新增交互入口时不得复用带文字的按钮变体；要么 icon-only，要么收进详情/次级页面。
- 约束三：已读语义 = 打开详情，不可撤回（与网关 `readAt` 单向一致）；若未来要"未读筛选"或"标记未读"，须先推翻本 Note 而不是悄悄加按钮。
- 约束四：`AnnouncementList.css` 不得出现硬编码颜色（既有 themeCss 守卫持续生效）。

## 验证

- `packages/ui/test/AnnouncementList.test.tsx` 重写：列表不内联正文、点开未读条目触发 `onMarkRead(id)` 且进入详情、已读条目不再调用、返回导航可回列表、标记失败在详情内以 alert 呈现、空态不变。
- `packages/ui/test/themeCss.test.ts`：公告 CSS 令牌守卫更新并以 `pnpm verify` 门禁确认。
- 实机（用户目测）：公告 Tab 列表为紧凑条目；点开见全文并自动变已读；Tab 角标随未读数变化；返回导航可用。
