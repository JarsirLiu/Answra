# Note：模式菜单超出窗口时被裁切

状态：已实施

## 问题

增加“对话”模式后，模式菜单包含四项，但较矮的窗口内容布局中最下面的“会议”无法看到。菜单使用绝对定位，不参与外壳高度测量；旧的高度预留只在面板关闭时生效。

## 涉及范围

- 代码/模块：`packages/ui/src/components/floating-bar/FloatingBar.tsx`、`FloatingBar.css`、`ModePicker.css`、`packages/ui/test/FloatingBarApp.test.tsx`
- UI/进程/协议/持久化表面：模式菜单展开时的浮条与面板垂直布局；不涉及 IPC 或持久化。
- 相关 Note：[对话模式与答题模式分离](../../implemented/feature/2026-10-17-separate-chat-and-exam-modes.md)

## 根因

`.mode-menu` 使用绝对定位，因此 `useFitContent` 测量的外壳高度不包含菜单。旧规则只在面板关闭时用固定三项的 padding 预留窗口高度；面板打开但高度不足时仍会裁掉菜单底部。

## 决定

面板打开时菜单保持绝对定位，覆盖在面板上，不改变面板位置和尺寸。只有面板关闭时菜单才进入正常布局流，让外壳按菜单实际高度扩展。由内容本身决定高度，不再以固定条目数计算预留空间。

## 修复

- `FloatingBar.tsx` 仅在菜单展开且面板关闭时给堆叠容器添加 `is-menu-in-flow` 状态类。
- `ModePicker.css` 默认让菜单绝对定位覆盖面板；仅在 `is-menu-in-flow` 状态下切换为正常布局。无面板时，菜单自身高度进入 `useFitContent` 测量范围。
- 删除浮条上按固定条目数计算的底部 padding。
- UI 测试覆盖面板关闭时菜单进入布局流、面板打开时菜单维持浮层，并确认两种状态都包含“会议”项。

## 影响表面

- 面板打开时菜单覆盖在面板上，不改变面板高度；面板关闭时悬浮窗会按菜单实际高度扩展。
- 菜单关闭时维持原有浮条与面板布局。

## 曾考虑的替代方案

- **继续使用绝对定位并手工增加预留条目数：** 舍弃，因为模式数量变化时还要同步维护 CSS 高度，容易再次裁切。
- **只在面板关闭时将菜单放入布局流：** 舍弃，因为较矮的面板仍可能小于菜单高度，无法覆盖该问题。

## 后果与防回退

- 面板关闭时模式菜单展开会让窗口增高；新增模式不需要同步修改窗口高度常量。
- 面板打开时必须保留菜单浮层行为；面板关闭时必须让完整菜单尺寸参与窗口测量，避免裁切。
