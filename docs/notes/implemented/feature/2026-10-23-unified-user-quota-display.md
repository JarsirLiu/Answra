# Note：用户额度积分统一展示

状态：已实施

## 问题

订阅用户的额度按积分记账，但网站侧栏仍展示余额金额，概览和桌面端也没有统一呈现免费用户 `default` 分组的可用额度。用户无法从账户页面判断当前能使用多少额度。

## 涉及范围

- 代码：AnswraSite `gateway/internal/service/user_quota_summary.go`、`gateway/internal/handler/user_quota_handler.go`、网站 dashboard、usage、admin 组件；Answra `apps/desktop/src/main/auth/authService.ts`、`packages/ui/src/components/panels/SettingsPanel.tsx`
- 跨端契约：网关 `GET /api/v1/user/quota`、管理员 `GET /api/v1/admin/users/:id/quota`；桌面凭据中的用户额度摘要
- 用户行为：网站侧栏、概览、用量页和桌面账户设置显示积分额度；管理员仍可进行账务余额调整
- 相关 Note：`2026-10-19-subscription-credits.md`、`2026-10-19-subscription-lifecycle-and-welfare.md`

## 决定

1. 生效付费订阅用户展示套餐名、周期总积分、已用积分、剩余积分、重置时间和到期时间。多个周期额度并存时，可用额度按当前最小剩余周期计算；不与免费账户来源相加。
2. 没有生效付费订阅的用户展示“免费版”。可用积分由有效福利剩余积分与账户可用额按固定 `CreditsPerUSD` 换算后相加，并说明来源及最近福利到期时间。页面不展示货币余额。
3. 网站和桌面端从网关统一额度摘要读取展示数据。额度计算留在网关服务，客户端不推算或重新换算。
4. 管理员用户管理以积分展示和调整账户额度，网关边界换算后沿用金额账本；成本、收益和订单继续按货币展示。模型用户成本为 0 时仍扣 0 积分，本次不增加免费请求定价。

## 影响表面

普通用户的网站侧栏、概览、用量页和桌面账户设置统一显示积分额度。管理员用户详情可查看统一额度摘要，余额金额只留在管理账务操作中。网关新增用户额度查询及管理员查询路由，不改变模型上游调用协议、账号选择或计费准入行为。

## 曾考虑的替代方案

- **继续在用户侧栏展示余额金额：** 与订阅用户按积分消费的实际口径不一致，也无法反映福利额度，舍弃。
- **让网站和桌面端分别汇总订阅、福利和账户余额：** 会复制规则且容易与服务端计费口径漂移；统一由网关服务计算，采用。
- **把免费账户换算积分并入付费订阅周期额度：** 两类额度的生命周期与扣减顺序不同，合并会误导用户，舍弃。
- **模型成本为零时另设固定免费请求次数：** 当前业务提案没有授权新的免费定价规则，保持实际扣 0 积分，舍弃。

## 后果与防回退

普通用户产品界面和管理员用户管理统一以积分呈现额度；支付订单金额、成本、收益和内部账本仍保留货币，因为它们表达交易或财务数据。`default` 是免费服务路由，不是付费套餐。后续额度展示必须继续读取网关摘要，不能将余额货币字段直接作为用户额度，也不能让客户端自行实现额度换算。
