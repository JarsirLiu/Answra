# Note：桌面端登录后同步账号信息与套餐额度

状态：已实施

## 问题

桌面端登录成功后，设置面板只显示档位名（「免费档/会员」或「已登录」），用户看不到自己是谁、有没有套餐、额度用掉多少。用户在本地联调验收时明确提出：账号信息、套餐等级、额度用量登录后必须可见，否则「登录了却不知道登的是谁、还能用多少」。桌面端 main 只拉了能力目录（`GET /api/v1/capabilities`），没有取站点已有的账号画像与订阅进度。

## 涉及范围

- 桌面端 `AuthStatus` 契约新增 `account`（邮箱/用户名）与 `quota`（已用百分比、到期时间、剩余天数）两个可选字段。
- 凭据文件（`desktop-auth.bin`）新增两项加密保存的展示画像；老记录缺字段时按 null 处理，不触发登出。
- 设置面板「账户」分组新增账号标识行与额度进度条；能力目录仍不渲染成权益（避免把接口面误当额度）。
- 站点/网关侧不需要改动：复用既有 `GET /api/v1/auth/me` 与 `GET /api/v1/subscriptions/progress`。

## 影响表面

- 未登录：与之前一致（「未登录」+「登录」）。
- 已登录且服务端有额度进度：账户分组显示档位名、邮箱（或用户名）与「本月额度 · 已用 N% · 剩余 D 天」进度条。
- 已登录但没有有效订阅：额度行固定显示「未开通套餐」（不隐藏、不空白）。
- 拉取失败：登录态不受影响，字段保持上一次有效值或 null，不弹错。
- 原来的兜底文案「模型调用由服务端额度控制，未开通时会提示原因」与「云端订阅：登录后按服务端额度调用」按用户验收意见删除——它们不携带额度信息，属冗余；额度只以账户分组下的进展数据表达。

## 决定

- 账号与额度走「画像」通道，与能力目录同一次账号画像拉取（`fetchProfile`）内完成，分别容错：能力目录失败沿用旧画像，账号/额度失败只回退各自字段。
- 两个字段在 `AuthStatus` 与凭据记录里都是**可选且可空**：站点允许用户名/邮箱二选一登录，任何一段缺失都不是错误。
- 客户端只做形状校验与展示，不推导金额、配额或档位语义；百分比按 0-100 夹取，三个字段都无法识别时整块按「无额度」处理。
- 请求携带 `Accept-Language`（来自 main 已持有的 locale），让服务端返回本地化套餐名。

## 曾考虑的替代方案

- **新增一个桌面专用聚合端点（`GET /api/v1/desktop/profile` 一次返回账号+套餐+额度）**：舍弃。需要改 Go 网关、加路由与契约测试，收益只是省一次请求；桌面端只在登录/刷新/冷启动拉取，频率极低，复用既有用户接口的耦合面更小。
- **把额度塞进能力目录响应**：舍弃。会让「接口目录」承担账号权益语义，站点侧本就把 `capabilities` 定义为「已实现的接口面」，混入额度会污染既有语义并让两端同时改契约。
- **额度与账号做成必填字段**：舍弃。历史凭据文件与旧网关没有这两个字段，必填会强制迁移或抛错；可选字段让版本升级与灰度都不需要额外状态机。
- **失败时把字段清空**：舍弃。刷新时瞬时网络失败会让面板闪回「无额度」；改为回退到调用方给的上一次有效值。

- **已登录但没有额度数据时显示兜底说明文本**：舍弃。用户验收反馈该文案冗余（额度位置应表达数据本身）；改为在账户分组内固定渲染「本月额度」行，无有效订阅时显示「未开通套餐」。代价是必须保证该行只在登录态渲染，未登录不得出现。

## 后果与防回退

- 每次账号画像拉取从 1 个请求变成 3 个（能力目录 + 账号 + 额度），登录/刷新/冷启动各一次，成本可忽略；若站点未来加聚合端点，只需替换 `AUTH_PATHS` 与解析函数，不改调用方。
- 额度行是登录态的固定组成：`authStatus.signedIn` 为真即渲染，`usedPercent` 非 null 才画进度条。「未开通套餐」只表示「拿不到额度数据」，不区分原因（无订阅或拉取未成功），措辞刻意保守。
- 「模型」分组只在本地来源分支渲染字段；云端分支不再输出任何状态说明，避免与账户分组的额度重复表达。
- 「能力目录 ≠ 额度」这条既有约束必须保留：新增展示不得把 `capabilities` 数量渲染成解锁数量。

## 验证

- `apps/desktop/test/authService.test.ts`：交换后状态与凭据记录包含 `account`/`quota`；目录不可用时仍登录成功且两字段为 null；`readAccount`/`readQuota` 覆盖单字段缺失、百分比夹取、无月度额度、空载荷四个分支；`AUTH_PATHS` 契约断言更新。
- `packages/ui/test/FloatingBarApp.test.tsx`：登录态推送包含账号与额度时，面板显示邮箱、「已用 38% · 剩余 42 天」与 `role="progressbar"`（`aria-valuenow=38`），且不显示「未开通套餐」；登录态但无额度时账户分组显示「本月额度 / 未开通套餐」；打包版（`localAvailable=false`）整块「模型」分组不渲染。
- `pnpm verify` 全绿（lint + 全包 typecheck + vitest + 架构守护）。
- 本地联调：站点 `127.0.0.1:3100` + 网关 `:8080` 走通登录后，面板可看到 `admin@answra.local`（该管理员账号本地无有效订阅，故额度区按「无额度」回落，属预期）。
