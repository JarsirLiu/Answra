# Note：CLI 登录等待与成功反馈缺失

状态：已实施

## 问题

CLI TUI 的 `/login` 只显示 5 秒的“正在打开浏览器”通知，而 OAuth 回调最长等待 5 分钟。等待通知消失后界面没有任何进行中状态；成功后登录函数又立即移除通知，用户看不到登录完成或账号信息。

## 涉及范围

- 代码/模块：`apps/cli/src/tui/runTui.tsx`、`apps/cli/test/tui/runTui.test.ts`
- UI/进程/协议/持久化表面：CLI TUI `/login` 通知与账户状态投影；不改变 OAuth、回调或凭据存储协议。
- 相关 Note：[CLI 欢迎页与账号登录交互](../feature/2026-11-14-cli-welcome-and-auth-flow.md)

## 根因

登录进度通知设置了 5 秒超时，但 OAuth 本地回调等待最长 5 分钟；成功路径仅更新 view store 账户状态，并在 `finally` 中移除进度通知，没有成功通知。

## 决定

登录等待期间必须持续展示可见状态；CLI 收到授权结果后，立即同步账户状态并明确告知用户结果。

## 修复

- 登录进度通知在授权流程结束前不超时。
- 成功时更新 TUI 账户状态，并替换进度通知为包含账号的成功反馈。
- 无账号资料时使用通用 Answra 账户文案，不展示或记录令牌。
- 失败时清理登录进度通知，让命令分派显示具体错误；授权码提示仍在所有路径清理。

## 曾考虑的替代方案

- **保留 5 秒超时并提高时长：** OAuth 等待时间不确定，任意固定时长都可能在回调前消失，因此不采用。
- **成功后只依赖状态面板：** 用户登录后需要即时反馈，不应要求额外运行 `/status` 才能确认结果，因此不采用。

## 后果与防回退

- `/login` 在浏览器授权期间持续显示等待状态；成功后状态行/状态面板数据与成功通知同步反映账户。
- 测试必须验证登录仍 pending 时通知存在，以及完成后账户状态和成功文案均更新。
