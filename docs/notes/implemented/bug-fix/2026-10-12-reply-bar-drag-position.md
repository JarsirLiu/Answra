# Note：回复条拖动位置稳定性

状态：已实施

## 问题

独立回复窗口虽然允许拖动，但主进程继续使用截图选区生成的旧锚点计算流式内容 resize 的位置。窗口可能因此跳回旧位置；拖到屏幕工作区以外时也可能难以找回。

## 根因

回复窗口控制器只在截图选区变化时更新 `position`，没有监听原生窗口移动事件，也没有对拖动后的边界做工作区约束。

## 涉及范围

- 代码/模块：`apps/desktop/src/main/replyBarWindowController.ts`、`apps/desktop/src/main/windowLayout.ts`
- UI/进程/协议/持久化表面：Electron 主进程管理的回复窗口位置和大小。
- 相关 Note：[Electron 捕获保护版本兼容](./2026-10-11-electron-capture-protection-compatibility.md)

## 决定

监听回复窗口 `move` 事件，以当前窗口 bounds 和展开方向反算回复条锚点；把完整窗口 bounds 限制在当前匹配显示器的 `workArea` 内。面板后续 resize 使用更新后的锚点。首次打开仍使用截图选区定位，关闭窗口后不跨回复工作流持久化用户坐标。

## 修复

- 手动移动回复窗口时更新锚点，保证流式内容高度变化后仍以用户放置的回复条位置展开。
- 越过当前显示器工作区边界时，将窗口位置夹回可见区域。
- 保留 resize 后的捕获保护重应用逻辑。

## 曾考虑的替代方案

- **只在拖动结束后保存坐标：** 舍弃；Electron 的结束移动事件并非所有支持平台都一致，且拖动中越界仍可能让窗口脱离工作区。
- **把位置持久化到应用设置：** 舍弃；本次问题是一个回复工作流内的 resize 跳位，不需要引入跨会话偏好与设置迁移。

## 后果与防回退

- 当前工作流中用户拖动的位置会在后续面板尺寸变化时保留；新截图仍会重新使用选区作为首次定位点。
- 位置约束使用操作系统工作区而非整块显示器边界，因此任务栏等保留区域不会被窗口覆盖。
- 捕获保护由窗口句柄持有，拖动不改变其状态；窗口尺寸变化时仍要重应用并保持实机兼容性验证。

## 验证

- 自动化：布局测试覆盖工作区夹取、手动位置反算；窗口控制器测试覆盖 move 事件后保留锚点。
- 自动化不能代替多显示器和操作系统拖动行为实测；本次未改变捕获保护 API 或 Electron 版本。
